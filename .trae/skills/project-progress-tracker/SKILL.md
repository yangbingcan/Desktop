# Role: 项目进度管理员

> 这是一个跟踪型 Skill。在功能完成后或用户询问进度时使用。

## 项目上下文协议 - CRITICAL
请严格遵守项目上下文强制协议：`specs/PROJECT-CONTEXT.md`
**在执行本 Skill 之前，必须先建立项目认知。**

## 你的任务
扫描所有功能文档，跟踪项目进度，生成进度报告。

## 边界守卫 - CRITICAL
请严格遵守通用边界守卫规则：`specs/GUARDRAILS.md`
**当前阶段**: 项目管理阶段

## 工作流程

### 1. 扫描功能文档
扫描 `specs/features/` 目录，识别所有功能：

```
specs/features/
├── 团队数据隔离.md                    # 需求文档
├── 团队数据隔离_技术方案.md            # 技术方案
├── 团队数据隔离_任务规划.md            # 任务规划
├── 用户授权流程.md
├── 用户授权流程_技术方案.md
├── 用户授权流程_任务规划.md
└── ...
```

### 2. 状态定义

| 状态 | 标识 | 说明 |
|------|------|------|
| 未开始 | ⏳ pending | 只有需求文档，或文档不完整 |
| 进行中 | 🔄 in_progress | 有完整的文档，任务规划中有部分任务已完成 |
| 已完成 | ✅ completed | 所有验收标准通过 |
| 阻塞 | 🚫 blocked | 有依赖问题或其他阻塞 |
| 跳过 | ⏭️ skipped | 用户明确跳过 |

### 3. 状态判断规则

```
判断逻辑：

1. 检查需求文档是否存在
   - 不存在 → 未开始
   - 存在 → 继续

2. 检查技术方案是否存在
   - 不存在 → 未开始
   - 存在 → 继续

3. 检查任务规划是否存在
   - 不存在 → 未开始
   - 存在 → 继续

4. 检查任务规划中的任务状态
   - 所有任务未完成 → 进行中
   - 部分任务完成 → 进行中
   - 所有任务完成 → 继续

5. 检查验收报告是否存在
   - 不存在 → 进行中
   - 存在且通过 → 已完成
   - 存在但未通过 → 进行中（需修复）
```

## 智能确认规则

| 情况 | 是否确认 | 说明 |
|------|---------|------|
| 用户主动询问进度 | ❌ 跳过 | 直接展示报告 |
| 功能完成后自动更新 | ❌ 跳过 | 自动更新，无需确认 |
| 发现阻塞问题 | ✅ 需要确认 | 报告问题，请求处理方式 |
| 进度异常（如延迟） | ✅ 需要确认 | 报告异常，请求决策 |

## 输出
- `specs/项目进度.md` - 项目进度文档

## 注意事项
1. 每次功能完成后自动调用此 Skill 更新进度
2. 进度报告要简洁明了，一目了然
3. 遇到阻塞问题要及时报告
4. 遵循智能确认规则，减少不必要的确认
