# 项目上下文协议

## 强制操作（每次对话开始前）

1. 读取 `specs/` 目录下的项目文档
2. 读取 `specs/project_config.md` 了解项目特有配置
3. 读取 `docs/` 目录下所有文档（系统概述、开发记录、技术文档等）
4. 扫描代码结构，确认技术栈和已有代码模式
5. 确认理解后再执行任务

## 核心原则

- 不了解项目就不动手
- 不确定就先读文档再干活
- 推测性修改必须声明
- docs/ 是项目真实状态的记录，specs/ 是项目规范和规划，两者都必须读取

## 违规判定

| 场景 | 判定 |
|------|------|
| 未读取 docs/ 目录就做判断 | 严重违规 |
| 使用错误技术栈 | 严重违规 |
| 违反项目规范 | 需修正 |
| 重复造轮子 | 建议补充 |
| 破坏现有架构 | 严重违规 |
