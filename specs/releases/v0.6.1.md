## 一、版本概述

v0.6.1 针对 `docs/开发记录/代码全面检查-2026-07-12.md` 的发现项实施修复，覆盖 **P0 / P1 / P2 可落地项**。核心修复：

1. **路由鉴权门禁（P0·C1）** — 此前 `beforeEach` 守卫形同虚设，任意用户可直达业务路由。新增轻量会话门禁：登录写 `localStorage` 标记，未登录访问非 `public` 路由重定向 `/login`。
2. **金额浮点漂移（P0·C2）** — 新增可参数化四舍五入 helper `utils/money.rs`，在聚合/落库边界统一 `round2`，收敛 `0.005` 级分位漂移（保留 `REAL` 存储，不动 DB schema）。
3. **生产破坏性命令门禁（P1·H1）** — `clear_all_data` 仅 `debug_assertions` 下可用，release 构建直接拒绝，杜绝生产误清空全库。
4. **UI 规范收敛（P2·M1）** — 20 个业务页 `text-[var(--tea-primary)]` 收敛为注册 token `text-tea-primary`；`--tea-content-1..4` 因明暗双值自适应予以保留。原 M3「`meta.public` 死配置」随 C1 修复自动消解。
5. **死依赖清理（P2·L4）** — `package.json` / `package-lock.json` 移除 `@vicons/ionicons5`、`@iconify-json/ic` 残留声明（源码早已无引用）。

配套修复：新增 `src-tauri/src/utils/mod.rs` 解决 `cargo check` 的 `E0583`（模块文件缺失）；清理 3 处确认未使用的 import 警告。

### 1.1 是否涉及数据库变更

**否**。金额方案采用「边界四舍五入」，不改变 `REAL`（f64）存储与任何表结构。因此按项目版本规则「无 DB 变更 → patch 递增」。

## 三、核心变更

### 3.1 轻量会话门禁（P0·C1）

**问题**：`beforeEach` 仅设置 `document.title` 后无条件 `next()`，登录页为单机演示 UI 壳（任意账号密码进入），无全局访问控制。

**修复**：
- `router/index.ts`：`beforeEach` 读取 `localStorage['tea-logged-in']`；未登录且目标非 `meta.public` → `next('/login')`；已登录访问 `/login` → `next('/')`。
- `Login.vue`：登录成功写入标记。
- `/login` 路由已有 `meta: { public: true }`（原 M3 死配置由此激活）。

**位置**：`tea-manage/src/router/index.ts`、`tea-manage/src/views/auth/Login.vue`

### 3.2 金额边界四舍五入（P0·C2）

**问题**：折扣分摊、积分累加、多单位换算等浮点运算可能产生分位漂移，长期累积导致账目不平。

**修复**：
- 新增 `utils/money.rs`：`RoundMode { HalfUp, HalfDown, Up, Down }` + `round_money(value, decimals, mode)` + `round2(value)`；非有限值归零。满足「四舍五入/不进位/进位/截断 + 保留位数参数化」需求。
- 在销售、退货、会员储值、供应商付款的聚合/落库边界统一 `round2`，避免多笔累加漂移进账。

**位置**：`tea-manage/src-tauri/src/utils/money.rs` 及上述 commands 文件

### 3.3 生产破坏性命令门禁（P1·H1）

**问题**：`clear_all_data` 在所有构建（含 release）注册，任意 invoke 可清空全库。

**修复**：`clear_all_data` 函数体首行 `if !cfg!(debug_assertions) { return Err("清空全库命令仅开发环境可用".into()); }`。release 下调用直接返回错误。

**位置**：`tea-manage/src-tauri/src/commands/dev_data.rs`

### 3.4 UI 规范收敛（P2·M1 / L4）

**问题**：业务页用 `text-[var(--tea-primary)]` 任意值上色，绕过注册 token；`package.json`/`package-lock.json` 残留已无引用的死依赖。

**修复**：脚本将 20 个 `.vue` 的 `text-[var(--tea-primary)]` 替换为 `text-tea-primary`（UnoCSS 注册 `#4A6741`）；从两个锁/声明文件移除 `@vicons/ionicons5`、`@iconify-json/ic`。`--tea-content-1..4` 因 `variables.css` 明暗双值自适应予以保留。

**位置**：20 个业务视图 + `package.json` + `package-lock.json`

## 六、风险评估

### 6.1 高风险项

无。鉴权为单机演示门禁（无后端用户表）；金额方案不动 schema，仅聚合边界收敛；生产门禁为纯拒绝短路。

### 6.2 中风险项

1. **鉴权强度**
   - 影响：会话标记存 `localStorage`，可被手动清除/伪造；单机本地应用可接受。
   - 缓解：若需更强保护，后续可引入真实登录体系（需用户表 + 后端校验，属独立需求）。

2. **金额四舍五入边界**
   - 影响：部分历史脏数据若已含漂移，新写入会被收敛，旧数据不变。
   - 缓解：仅新聚合结果 `round2`，不影响存量；如需全量校准需数据迁移（独立需求）。

### 6.3 低风险项

- `cargo check` 残留 27 条警告（未使用变量、`pub use schema::*` 重导出），均为预存项、非阻断，留待后续清理。
