## 一、版本概述

核心交付：

## 三、变更描述

### 3.1 BUG #1：PurchaseItemInput 缺少 rename_all（CRITICAL）

**问题描述**：
- 后端 `PurchaseItemInput`（[inventory.rs:104](file:///d:/AI/AI/开发/茶叶店管理/tea-manage/src-tauri/src/models/inventory.rs)）未声明 `#[serde(rename_all = "camelCase")]`
- 后端期望字段：`product_id, unit_id, quantity, unit_price`（默认 snake_case）
- 前端发送字段：`productId, unitId, quantity, unitPrice`（camelCase）
- **影响**：采购入库（`purchase_in`）时，前端 `items` 数组中每个对象的 camelCase 字段会被后端 serde 忽略，导致反序列化失败

**修复方案**：
```rust
#[derive(Debug, Clone, Serialize, Deserialize)]
#[serde(rename_all = "camelCase")]  // 新增
pub struct PurchaseItemInput {
    pub product_id: String,
    pub unit_id: String,
    pub quantity: i64,
    pub unit_price: f64,
}
```

**业务影响**：无（仅通信层修复，业务逻辑不变）

### 3.2 BUG #2：PayMethod 枚举值不一致（CRITICAL）

**问题描述**：
- 后端 `PayMethod` 枚举 `rename_all="snake_case"`，序列化为：`cash, wechat, alipay, member_card, mixed`
- 前端 `PayMethod` 类型：`'cash' | 'wechat' | 'alipay' | 'memberBalance' | 'combined'`
- 不匹配项：`member_card ≠ memberBalance`，`mixed ≠ combined`
- **影响**：销售订单 `pay_method` 字段反序列化会失败

**修复方案**（后端改为前端命名）：
```rust
#[derive(Debug, Clone, Copy, PartialEq, Eq, Serialize, Deserialize)]
pub enum PayMethod {
    Cash,
    Wechat,
    Alipay,
    #[serde(rename = "memberBalance")]
    MemberCard,  // 会员卡（用会员余额支付）
    #[serde(rename = "combined")]
    Mixed,       // 组合支付
}
```

**业务影响**：无（业务代码用 `String` 比较而非枚举，且 `commands/sales.rs:412` 已使用 `"memberBalance"` 字符串判断）

### 3.3 BUG #3：PayStatus 枚举值不一致（CRITICAL）

**问题描述**：
- 后端 `PayStatus` 枚举 `rename_all="snake_case"`，序列化为：`pending, paid, refunded`
- 前端 `PayStatus` 类型：`'unpaid' | 'paid' | 'refunded'`
- 不匹配项：`pending ≠ unpaid`
- **影响**：销售订单 `pay_status` 字段反序列化会失败

**修复方案**（后端改为前端命名）：
```rust
#[derive(Debug, Clone, Copy, PartialEq, Eq, Serialize, Deserialize)]
pub enum PayStatus {
    #[serde(rename = "unpaid")]
    Pending,  // 待支付
    #[serde(rename = "paid")]
    Paid,     // 已支付
    #[serde(rename = "refunded")]
    Refunded, // 已退款
}
```

**同步修改**：
- `commands/sales.rs:659`：`pay_status: "pending"` → `pay_status: "unpaid"`（创建挂单时）
- `db/schema.rs:718`：`pay_status TEXT NOT NULL DEFAULT 'pending'` → `DEFAULT 'unpaid'`

**业务影响**：无（业务语义不变，"pending"和"unpaid"都表示"待支付"）

### 3.4 BUG #4：create_sale_order 外键约束失败（CRITICAL，用户实测发现）

**问题描述**：
- 用户在实际使用中点击「结算」按钮时，前端弹窗提示「结算失败：FOREIGN KEY constraint failed」
- **根因**：`create_sale_order` 函数原代码在循环内**先插 `sales_items`**（其 `order_id` 字段有外键引用 `sales_orders.id`），**后插 `sales_orders`** 主单
- 由于 `Database::new()` 启用了 `PRAGMA foreign_keys = ON`（IMMEDIATE 模式），第一轮循环执行 `INSERT INTO sales_items` 时 `order_id` 在 `sales_orders` 中尚不存在，立即触发外键约束失败
- **测试盲区**：后端 25 个 sales.rs 测试中**没有任何测试调用 `create_sale_order`**！测试了 `hold_order`、`get_held_orders` 等其他函数，但唯独漏了最核心的结算命令

**修复方案**（调整插入顺序，先主单后明细）：

1. 在循环前声明 `pending_items: Vec<(...)>` 暂存待插入的明细
2. 循环中将 `INSERT INTO sales_items` 改为 `pending_items.push(...)`
3. 在 `INSERT INTO sales_orders` 之后循环执行 `INSERT INTO sales_items`

**新增回归测试**（5 个，添加在 sales.rs 测试模块末尾）：
- `test_create_sale_order_sql_basic`：验证修复后的插入顺序不会触发外键约束失败
- `test_create_sale_order_sql_foreign_key_regression`：回归测试，验证先插 sales_items 确实会触发外键约束失败
- `test_create_sale_order_sql_with_stock_deduct`：验证结算流程中的库存扣减
- `test_create_sale_order_sql_with_member_points`：验证含会员的结算流程（积分更新 + 消费金额累计）
- `test_create_sale_order_sql_stock_flow_record`：验证结算时记录库存流水

**业务影响**：✅ 修复后用户可正常完成结算流程。修复仅调整 SQL 执行顺序，业务逻辑零变更

**教训**：本次 BUG 暴露了测试体系的重大缺口 —— 后端测试覆盖了辅助函数但漏了核心命令。后续应在测试清单中明确标注「核心业务命令必须有用例覆盖」

### 3.5 BUG #5：build_category_tree clone 后修改 map 不影响 roots（MEDIUM）

**问题描述**：
- `build_category_tree` 函数（[db/queries.rs:432](file:///d:/AI/AI/开发/茶叶店管理/tea-manage/src-tauri/src/db/queries.rs)）在构建分类树时，根节点被 clone 后 push 到 `roots` 数组
- 后续子节点添加到 `map` 中的根节点（通过 `map.get_mut(&parent_id)`），而非 `roots` 中的 clone
- 导致 `roots` 中根节点的 `children` 永远为空 —— 前端分类树只显示一级分类，无法展开子分类

**修复方案**（用 `root_ids` 延迟提取根节点）：
1. 循环中只记录根节点 id 到 `root_ids`，不 push 到 `roots`
2. 子节点用 `map.remove(&node_id)` 取出（避免 clone），添加到父节点的 `children`
3. 循环结束后，从 `map` 中提取根节点（此时 children 已被正确填充）

**业务影响**：无（修复后分类树能正确显示多级分类，业务逻辑不变）

### 3.6 BUG #6：create_return_order 先插 return_items 后插 return_orders（MEDIUM）

**问题描述**：
- `create_return_order` 函数（[commands/return_order.rs:97](file:///d:/AI/AI/开发/茶叶店管理/tea-manage/src-tauri/src/commands/return_order.rs)）在循环内先插 `return_items`（其 `order_id` 字段有外键引用 `return_orders.id`），后插 `return_orders` 主单
- 与 BUG #4（create_sale_order）完全相同的根因：SQLite 外键约束 IMMEDIATE 模式下，第一轮循环就触发 FOREIGN KEY constraint failed

**修复方案**（与 create_sale_order 相同的暂存策略）：
1. 循环前声明 `pending_items: Vec<(...)>` 暂存待插入的明细
2. 循环中将 `INSERT INTO return_items` 改为 `pending_items.push(...)`
3. 在 `INSERT INTO return_orders` 之后循环执行 `INSERT INTO return_items`

**业务影响**：无（修复后退货出库功能可正常使用，业务逻辑零变更）

### 3.7 BUG #7：PayMethod 枚举未加 rename_all="lowercase"（LOW）

**问题描述**：
- `PayMethod` 枚举的 `Cash/Wechat/Alipay` 未加 `#[serde(rename_all = "lowercase")]`
- 默认序列化为 `"Cash"/"Wechat"/"Alipay"`（首字母大写）
- `as_str()` 方法返回小写 `"cash"/"wechat"/"alipay"`
- 前端期望小写 `"cash"/"wechat"/"alipay"`
- 三者不一致（serde 序列化 ≠ as_str() ≠ 前端期望）

**影响评估**：
- 实际影响较小 —— 业务代码使用 `Option<String>` 而非 `PayMethod` 枚举存储支付方式
- 但枚举定义不一致是代码质量问题，应修复

**修复方案**：
```rust
#[derive(Debug, Clone, Copy, PartialEq, Eq, Serialize, Deserialize)]
#[serde(rename_all = "lowercase")]  // 新增
pub enum PayMethod {
    Cash,        // → "cash"
    Wechat,      // → "wechat"
    Alipay,      // → "alipay"
    #[serde(rename = "memberBalance")]  // 覆盖 rename_all
    MemberCard,  // → "memberBalance"
    #[serde(rename = "combined")]       // 覆盖 rename_all
    Mixed,       // → "combined"
}
```

**业务影响**：无（业务代码使用 String 而非枚举，serde 属性变更不影响业务逻辑）

## 六、风险评估

### 6.1 数据库变更风险

**变更内容**：`sales_orders.pay_status` 默认值 `'pending'` → `'unpaid'`

**影响范围**：
- **新数据**：新建挂单时 `pay_status` 默认为 `'unpaid'`，与前端类型一致 ✅
- **已有数据**：已有的 `pay_status = 'pending'` 记录**不会被自动迁移**
  - 这些记录返回给前端时，前端类型检查可能不通过
  - 但实际运行时 JavaScript 不会因字符串类型不匹配而报错
  - **建议**：若已有挂单数据，可执行 `UPDATE sales_orders SET pay_status = 'unpaid' WHERE pay_status = 'pending'` 进行数据迁移

### 6.2 兼容性风险

- **前端兼容性**：✅ 完全兼容（修复方向就是统一为前端命名）
- **后端兼容性**：✅ 完全兼容（PayMethod/PayStatus 枚举未被业务代码使用，仅作为类型定义存在）
- **API 兼容性**：✅ 完全兼容（IPC 接口签名未变，只是序列化值统一）

### 6.3 回滚方案

如需回滚到 v0.3.2 行为：
1. 撤销 `inventory.rs` 中 `PurchaseItemInput` 的 `#[serde(rename_all = "camelCase")]`
2. 撤销 `sales.rs` 中 `PayMethod` 和 `PayStatus` 的 `#[serde(rename = "xxx")]`
3. 撤销 `commands/sales.rs` 中 `pay_status: "unpaid"` 改回 `"pending"`
4. 撤销 `schema.rs` 中 `DEFAULT 'unpaid'` 改回 `'pending'`
