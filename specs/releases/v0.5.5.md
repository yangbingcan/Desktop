## 一、版本概述

v0.5.5 是 v0.5.4 之后的**标题栏融合与全站按钮主题适配专项修复版**，解决用户反馈的 6 个核心问题：

1. **侧边栏虚线装饰错位** — 左侧菜单分组标题的虚线装饰伪元素 `tea-sider-group::after` 视觉效果像错位的装饰条，移除该装饰，保留激活态发光竖条
2. **主题切换遮罩视觉效果** — body/app-layout/content 各层均使用半透明背景 `var(--tea-content-bg)`（rgba 0.85），主题切换时叠加产生"层遮罩"视觉效果。改为实色 `var(--tea-content-bg-solid)`
3. **按钮深浅色主题适配不全** — Naive UI 的 error/warning/success/info/ghost/text 类型按钮未在 n-overrides.css 中覆盖，深色模式下 default 按钮显示异常
4. **会员管理无数据显示** — MemberList.vue 误用 `<n-table>`（HTML 表格组件），不支持 columns/data props；改为 `<n-data-table>`
5. **视图紧凑度不一致** — PurchaseList、ReturnList、suppliers、settings、barcodes、print-templates 仍使用 `p-6/mb-4/text-xl` 旧类，与 ProductList 紧凑设计不一致
6. **标题栏未与应用融为一体** — 顶部标题栏仍是独立长条；关闭原生装饰后自实现最小化/最大化/关闭按钮 + 拖拽区域

### 1.1 设计理念

> **核心原则**：
> 1. 通过实色背景终结"层遮罩"视觉问题
> 2. 通过完整的按钮类型覆盖保证主题一致性
> 3. 通过提取通用紧凑设计类（tea-page/page-header/filter-card）统一全站视图
> 4. 通过 Tauri 2.x 自实现窗口控制按钮实现标题栏融入应用
>
> **范围限定**：**不改业务逻辑、不改路由、不改 Store、不改后端**
> **兼容性**：v0.5.0 / v0.5.1 / v0.5.2 / v0.5.3 / v0.5.4 的所有功能 100% 保留（纯样式 + 配置变更）

### 1.2 是否涉及数据库变更

**否**，本次为纯前端样式 + Tauri 配置变更，不涉及数据库 schema 变更。按版本规则 → patch 版本递增。

## 三、核心变更

### 3.1 侧边栏虚线装饰移除

**问题**：左侧菜单分组标题左侧显示一条虚线，用户反馈像"错位的装饰条"。

**根因**：`tea-sider:not(.tea-sider-collapsed) .tea-sider-group::after` 伪元素绘制了 dashed 竖线作为"树状连接线"装饰，但视觉效果与设计意图不符。

**修复**：移除 `tea-sider-group::after` 虚线伪元素规则；保留激活态分组标题的发光竖条（`tea-sider-group-has-active > .tea-sider-section::before`）以指示当前激活分组。

**位置**：[tea-manage/src/components/layout/Sidebar.vue](file:///d:/AI/AI/开发/茶叶店管理/tea-manage/src/components/layout/Sidebar.vue)（lines 461-497 已移除）

### 3.2 主题切换遮罩修复

**问题**：主题色切换时有一层遮罩的视觉效果。

**根因**：`html, body, #app` 和 `.tea-app-layout`、`.tea-app-content` 均使用半透明背景 `var(--tea-content-bg)`（`rgba(247, 244, 240, 0.85)`），主题切换时各层半透明背景叠加产生"层遮罩"视觉效果。

**修复**：将这些元素的背景改为实色 `var(--tea-content-bg-solid)`，仅保留卡片/标题栏等装饰性元素的半透明效果。

**位置**：
- [tea-manage/src/styles/globals.css](file:///d:/AI/AI/开发/茶叶店管理/tea-manage/src/styles/globals.css) - `html, body, #app` 背景
- [tea-manage/src/components/layout/AppLayout.vue](file:///d:/AI/AI/开发/茶叶店管理/tea-manage/src/components/layout/AppLayout.vue) - `.tea-app-layout` / `.tea-app-content` 背景

### 3.3 按钮全面主题适配

**问题**：部分按钮没有正确背景色，导致深色/浅色主题下显示有问题。

**根因**：n-overrides.css 中只覆盖了 `primary-type` 和默认类型按钮，缺失 error/warning/success/info/ghost/text 类型的覆盖，导致深色模式下 default 按钮透明背景与文字色冲突。

**修复**：在 n-overrides.css 中补充以下覆盖：
1. **error-type 按钮**：红色背景 + 白色文字 + hover 浅红色 + active 深红色
2. **warning-type 按钮**：橙色背景 + 白色文字 + hover 浅橙色 + active 深橙色
3. **success-type 按钮**：绿色背景 + 白色文字 + hover 浅绿色 + active 深绿色
4. **info-type 按钮**：蓝色背景 + 白色文字 + hover 浅蓝色 + active 深蓝色
5. **ghost 模式**（5 种类型）：透明背景 + 对应类型边框和文字色 + hover 时对应类型淡色背景
6. **text-type 按钮**：无背景无边框 + hover 时主色淡色背景 + error 子类型特殊处理
7. **深色模式 default 按钮**：背景使用实色 `var(--tea-surface-2)`，hover 时 `var(--tea-surface-3)`

**位置**：[tea-manage/src/styles/n-overrides.css](file:///d:/AI/AI/开发/茶叶店管理/tea-manage/src/styles/n-overrides.css) - 第 330-498 行

### 3.4 会员管理无数据显示修复

**问题**：会员管理页面不显示数据，但数据库实际有数据。

**根因**：MemberList.vue 使用 `<n-table :columns :data>`，但 `n-table` 是基础 HTML 表格组件，不支持 `columns` 和 `data` props（这是 `n-data-table` 的 API）。

**修复**：完整重写 MemberList.vue，改用 `<n-data-table>`，并参照 ProductList.vue 应用紧凑设计模式（tea-page/page-header/filter-card/n-data-table/render 函数/语义变量）。

**位置**：[tea-manage/src/views/members/MemberList.vue](file:///d:/AI/AI/开发/茶叶店管理/tea-manage/src/views/members/MemberList.vue)

### 3.5 视图统一紧凑化优化

**问题**：PurchaseList、ReturnList、suppliers、settings、barcodes、print-templates 等视图仍使用 `p-6/mb-4/text-xl` 旧类，与 ProductList 紧凑设计不一致。

**修复策略**：
1. 将 ProductList 中的通用样式（tea-page/page-header/page-title/filter-card/filter-row/filter-input/filter-select/table-card）提取到 globals.css 作为全局共享类
2. 各视图改为使用这些共享类，移除冗余的 scoped 样式
3. 同时清理未使用的代码（如 barcodes/index.vue 中的 onSelect、selectedRows）

**位置**：
- [tea-manage/src/styles/globals.css](file:///d:/AI/AI/开发/茶叶店管理/tea-manage/src/styles/globals.css) - 新增通用工具类（lines 625-750）
- 6 个视图文件（详见 2.2 节）

### 3.6 标题栏融合应用

**问题**：顶部标题栏未与应用融为一体，仍是单独的一条长条，缺乏一体感。

**修复方案**：

**步骤 1 - 关闭原生装饰**：
- `tauri.conf.json` 中 `decorations: false` 关闭原生标题栏
- `transparent: false` 保持窗口不透明

**步骤 2 - 添加窗口操作权限**：
- `capabilities/default.json` 中添加 7 个 `core:window:*` 权限：
  - `allow-minimize` / `allow-maximize` / `allow-unmaximize` / `allow-toggle-window-maximized`
  - `allow-close` / `allow-start-dragging` / `allow-is-maximized`

**步骤 3 - 自实现窗口控制按钮**：
- TitleBar.vue 重构，添加三按钮（最小化/最大化-还原/关闭）
- 使用 `data-tauri-drag-region` 属性使标题栏可拖拽移动窗口
- 动态加载 `@tauri-apps/api/window` 的 `getCurrentWindow()` API
- 监听 `onResized` 事件同步最大化状态，切换按钮图标（方框 → 双方框）
- Web 环境下（非 Tauri）API 调用静默降级，不影响开发预览
- 按钮样式融入应用：实色背景 + 主题变量适配 + 关闭按钮红色 hover

**位置**：

- [tea-manage/src-tauri/capabilities/default.json](file:///d:/AI/AI/开发/茶叶店管理/tea-manage/src-tauri/capabilities/default.json)

## 六、风险评估

### 6.1 高风险项

无。本次为纯样式 + Tauri 配置变更，不影响业务逻辑。

### 6.2 中风险项

1. **Tauri 窗口控制按钮在 Web 预览模式下不工作**
   - 影响：开发预览模式下点击最小化/最大化/关闭无响应
   - 缓解：代码已通过 `__TAURI_INTERNALS__` 检测，Web 模式下静默降级，控制台警告但不报错
   - 验证：在 Tauri 桌面环境下 `npm run tauri dev` 完整验证

2. **`decorations: false` 在某些 Linux 窗口管理器下可能行为不一致**
   - 影响：Linux 下窗口可能无边框但无法移动
   - 缓解：已通过 `data-tauri-drag-region` 实现拖拽，覆盖大部分场景

### 6.3 低风险项

1. **barcodes/index.vue 表格列类型定义不规范**
   - 当前 `barcodeColumns` 中使用了 `slot: 'barcode'` 老式 API
   - 此页面功能仍在开发中（"功能开发中" 提示），暂不影响功能
   - 后续完善时可改为标准 `render` 函数

### 技术细节

#### 遮罩残留根因分析

Naive UI 抽屉/弹窗关闭时使用 `fadeInTransition`（0.2s opacity 过渡）：
1. 用户点击关闭 → `settingsOpen.value = false`
2. Vue 触发 `leave` 过渡 → mask 的 opacity 从 1 → 0（0.2s）
3. 如果在此 0.2s 窗口内 `applyToDOM()` 修改了 `<html>` 的 `data-theme`/`data-primary` 等属性
4. 浏览器触发**全页样式重算（recalculate style）**
5. 样式重算可能**中断/取消**正在进行的 CSS transition
6. mask 的 opacity 卡在中间状态（如 0.5）→ 视觉残留

**解决方案**：双 `requestAnimationFrame` 延迟 `applyToDOM` 调用，确保属性变更在过渡完成后的下一帧执行（~32ms 延迟，远超 200ms 过渡窗口的"安全区域"）。

#### 按钮颜色根因分析

Naive UI 按钮 CSS 类名组合：
- `n-button--primary-type` + `n-button--ghost` = ghost primary 按钮
- `n-button--primary-type`（无 ghost）= regular primary 按钮

问题：` .n-button--primary-type { color: #FFFFFF !important }` 同时命中 regular 和 ghost 按钮，覆盖了 ghost 按钮的对应色文字。

**解决方案**：所有 regular 按钮规则添加 `:not(.n-button--ghost):not(.tea-btn-text)`，确保只命中真正的 regular 按钮。

### 技术细节

#### 遮罩残留根因分析（第四轮终极定位）

前几轮修复集中在 `applyToDOM()` 的双 rAF 延迟，但用户反馈仍未解决。本轮通过 Playwright 实际检查 DOM 发现：

1. Naive UI 抽屉关闭时，`.n-drawer` 元素被 v-if 卸载，但 `.n-drawer-container` 延迟卸载
2. 此时 `[data-theme='dark'] .n-drawer-container` CSS 规则仍匹配空 container
3. 该规则设置 `background: var(--tea-drawer-bg) !important`（#1F1812）
4. 空 container 是 `position: fixed; top: 0; left: 0; width: 100vw; height: 100vh`
5. 结果：全屏深色背景覆盖 → 用户看到的"遮罩残留"

**关键证据**：Playwright 检查显示空 container `background: rgb(31, 24, 18); width: 1280; height: 720; childCount: 0`

#### 按钮 ghost-type class 发现

通过 Playwright 检查 Naive UI 实际生成的按钮 class：

| 按钮配置 | 实际生成的 class | 之前 CSS 排除的 class |
|---------|----------------|---------------------|
| `type: 'primary', ghost: true` | `n-button--primary-type n-button--ghost-type` | `n-button--ghost`（不匹配！） |
| `type: 'error', ghost: true` | `n-button--error-type n-button--ghost-type` | `n-button--ghost`（不匹配！） |
| 某些 dashboard 按钮 | `n-button--ghost` | `n-button--ghost`（匹配） |

Naive UI 在不同情况下生成 `n-button--ghost` 或 `n-button--ghost-type`，需要同时处理两种。
