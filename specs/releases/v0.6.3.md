# 茶易管 v0.6.3 版本说明

- **版本**：0.6.3（patch，无数据库结构变更）
- **日期**：2026-07-14
- **类型**：代码审查修复 + 业务信息化补全

## 变更概要

本次发布完成「全面代码审查」后的 P0 关键修复，并补全销售历史/经营报表能力，
将首页从 Mock 数据切换为真实经营指标。

### 一、P0 关键 Bug 修复（审查确认，已逐行复核）

**后端（Rust / SQLite）**
- `C1` `inventory.rs` 采购单修改反向还原：原按写死 `stock_grams` 且按原始全量扣减 →
  改为按 `product_type` 选择 `stock_grams`/`stock_units`，并按当前批次剩余量精确回滚，消除计件商品错乱与负库存风险。
- `C2` `inventory.rs` `damage_out` / `adjust_stock`：原仅动 `stock_grams` →
  改为按 `product_type` 选择正确库存列扣减/调整，计件商品库存现在正确维护。
- `C3` `dev_data.rs` `seed_demo_data`：补 `cfg!(debug_assertions)` 生产门禁，防止生产库被演示数据清空。
- `G1` `inventory.rs` 采购金额：采购明细 `subtotal` 与单据 `total_amount` 聚合处加 `round2`，消除 f64 累加漂移。
- `G2` `supplier_payments.rs` 供应商余额：`balance` 加 `round2`。
- `G4` `sales.rs` 积分抵扣：无会员时使用积分抵扣直接报错（避免凭空优惠）。
- `G5` `sales.rs` 挂单 `pay_status`：由 `'pending'` 修正为 `'unpaid'`，与取单/前端 PayStatus 类型一致（同步修正测试）。
- `G6` `sales.rs` 会员余额支付：无会员时直接报错，避免账目与支付记录脱节。

**前端（Vue / TS）**
- `F1` `inventory/index.vue` 采购入库弹窗：补「入库单位」选择控件，修复 `unitId` 恒空导致校验失败的不可用问题。
- `F2` `inventory/index.vue` 采购入库：补「供应商」选择，修复 `supplierId` 恒 undefined。
- `S4` `sales/index.vue` 取单重建会员：恢复真实会员 points/balance（原硬编码 0 导致会员卡支付误拒）。
- `S5` `print.ts` `buildReceiptHTML`：动态字段统一 `esc` 转义，修复 XSS。

（审查误判已纠正：`S1` 仅为折扣"标签"口径展示问题，后端按会员等级重算、实收金额正确；`S6` PurchaseDetail.vue 经复核为完整页面，无需修复。）

### 二、业务信息化补全（Q1：报表 + 销售历史 + 首页真数据）

- 新增后端命令 `get_sale_orders`：按日期区间 / 会员 / 商品筛选已完成销售订单，分页返回（含每行商品数）。
- 新增后端命令 `get_dashboard_stats`：今日订单数、今日销售额（实付合计）、低库存预警数（称重<500g / 计件<20个）、新增会员数。
- 前端 `api/sales.ts` 增加 `getSaleOrders` / `getDashboardStats`；`types/index.ts` 增加 `SaleOrderSummary` / `DashboardStats` / `SaleOrderQuery`。
- `dashboard/components/TodayStats.vue`：由 Mock 切换为调用 `get_dashboard_stats` 的真实数据（带加载态）。
- 新增「销售报表」页 `views/reports/SalesHistory.vue`：日期区间 / 会员 / 商品筛选 + 明细表 + 本页销售额合计；
  接入路由 `/reports/sales` 与侧边栏「销售报表」菜单。
