## 一、版本概述

v0.3.4 修复商品档案编辑时「商品类型」和「基准单位」修改无效的问题。

**根因**：`ProductUpdate` 结构体、`update_product` SQL 构建、前端 `ProductUpdateInput` 类型和前端表单提交四层均缺少 `product_type`（商品类型）和 `base_unit`（基准单位）字段，导致编辑保存时这两个字段不会被发送和更新到数据库。

**修复范围**：后端 Rust 模型 + 命令 + 前端类型 + 前端表单，共修改 4 个文件。

## 三、变更描述

### 3.1 BUG #8：商品档案编辑商品类型和基准单位无效（CRITICAL）

**问题描述**：
编辑商品时，修改「商品类型」（称重/计件）或「基准单位」（g/pcs）字段，点击保存后页面跳转，重新进入编辑页面发现值恢复为修改前的状态。

**根因分析**：
- `ProductUpdate` 结构体缺少 `product_type` 和 `base_unit` 字段 → serde 反序列化时忽略前端传入值
- `update_product` 命令的 SQL 构建未处理这两个字段 → DB 未更新
- 前端 `ProductUpdateInput` 类型未定义这两个字段 → TS 类型检查无提示
- 前端 `ProductForm.vue` 的 `handleSubmit` 未发送这两个字段 → 数据链断开

**修复方案**：
1. 后端模型 `ProductUpdate` 添加 `product_type: Option<ProductType>`（配 `#[serde(rename = "type")]`）和 `base_unit: Option<BaseUnit>`
2. 后端命令 `update_product` 添加 `product_type` 和 `base_unit` 的 SQL SET 逻辑（枚举转数据库字符串）
3. 前端类型 `ProductUpdateInput` 添加 `type` 和 `baseUnit` 可选字段
4. 前端表单 `handleSubmit` 将 `form.type` 和 `form.baseUnit` 传入更新请求

**业务影响**：无（修复后用户可正常修改商品类型和基准单位）
