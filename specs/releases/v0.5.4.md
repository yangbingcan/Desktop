## 一、版本概述

v0.5.4 是 v0.5.3 之后的**首页与商品档案专项 UI 修复版**，解决用户反馈的 3 个核心问题：

1. **首页图标不可见** — QuickActions / TodayStats 图标颜色与同色相浅底背景对比度仅 3.2:1，不达 WCAG AA。新增 `--tea-icon-*` 系列图标专用色变量（更深/更亮），对比度 ≥ 5:1
2. **商品档案深色模式固定列穿透** — 横向滚动时编码/名称（左固定）和操作（右固定）显示下层内容。根因是深色模式下 `n-data-table-td` 被强制 `transparent`，sticky 固定列无背景遮挡。修复为实色 `surface-2`
3. **商品档案浅色模式删除按钮无底色** — `ghost: true` 导致空心透明样式。改为实心红色按钮

### 1.1 设计理念

> **核心原则**：通过新增 CSS 变量分层（`--tea-icon-*` ≠ `--tea-accent-*`）和实色背景规则，终结"图标同色"和"固定列穿透"两类问题
> **范围限定**：**不改业务逻辑、不改路由、不改 Store、不改后端**
> **兼容性**：v0.5.0 / v0.5.1 / v0.5.2 / v0.5.3 的所有功能 100% 保留（纯样式 + 配置变更）

### 1.2 是否涉及数据库变更

**否**，本次为纯前端样式修复，不涉及数据库 schema 变更。按版本规则 → patch 版本递增。

## 三、核心变更

### 3.1 新增图标专用色 token（`--tea-icon-*`）

#### 背景

v0.5.2 引入的 `--tea-accent-*` 系列（success/info/warning/danger 等）主要用于边框、线条、强调色。但在 QuickActions / TodayStats 中被错误用作图标 color，与同色相浅底背景 `--tea-accent-*-bg` 搭配时，对比度仅 3.2:1（不达 WCAG AA）。

#### 色值设计原则

| 场景 | 浅色模式 | 深色模式 |
|------|---------|---------|
| 用于边框/线条 | `--tea-accent-*`（中等深度） | `--tea-accent-*`（中等亮度） |
| **用于图标/数值** | **`--tea-icon-*`（更深，≥ 5:1）** | **`--tea-icon-*`（更亮，≥ 7:1）** |
| 用于背景 | `--tea-accent-*-bg`（同色相浅底） | `--tea-accent-*-bg`（同色相暗底） |

#### 完整色值表

| 变量 | 浅色模式 | 与同色相浅底对比度 | 深色模式 | 与暗色背景对比度 |
|------|---------|-------------------|---------|----------------|
| `--tea-icon-primary` | `#8A5A30` | 5.6:1 | `#E0A55C` | 9.2:1 |
| `--tea-icon-success` | `#2D5C2C` | 6.1:1 | `#A8D2A6` | 10.5:1 |
| `--tea-icon-info` | `#1A4D80` | 7.2:1 | `#9CC5E8` | 8.8:1 |
| `--tea-icon-warning` | `#8A4A0F` | 5.8:1 | `#F0C896` | 11.2:1 |
| `--tea-icon-danger` | `#8A2A30` | 5.9:1 | `#F0AAB0` | 9.5:1 |
| `--tea-icon-purple` | `#5B3FAE` | 5.4:1 | `#C4A0FF` | 8.6:1 |
| `--tea-icon-emerald` | `#0F7A55` | 5.7:1 | `#6EE7B7` | 12.1:1 |
| `--tea-icon-gray` | `#4A5260` | 6.3:1 | `#B0B7C3` | 9.8:1 |

### 3.2 修复商品档案深色模式固定列穿透

#### 问题机制

Naive UI 的 `n-data-table` 固定列实现依赖 `position: sticky`：
- sticky 元素需要**不透明背景**才能遮挡下层滚动内容
- 浅色模式下 td 默认有白色背景，所以不穿透
- 深色模式下被 v0.5.2 兜底规则强制 `transparent`，导致穿透

#### 修复对比

| 场景 | 修复前 | 修复后 |
|------|--------|--------|
| 普通行 td 背景 | `transparent` | `var(--tea-surface-2)` = `#1F1812` |
| 斑马纹行 td 背景 | `var(--tea-surface-3)` = `#251D16` | 不变（已有规则覆盖） |
| hover 行 td 背景 | `var(--tea-hover-bg)` 半透明 | `var(--tea-surface-hover)` = `rgba(196,149,106,0.12)` |
| 固定列（编码/名称/操作） | 透明，穿透下层 | 实色，遮挡下层 ✓ |

### 3.3 修复删除按钮样式

#### 修复对比

| 属性 | 修复前（ghost） | 修复后（实心） |
|------|----------------|---------------|
| 背景 | 透明 | 红色（Naive UI error 默认） |
| 文字色 | 红色 | 白色 |
| 边框 | 红色 | 无 |
| 视觉效果 | 空心弱化 | 强烈警示 ✓ |

### 3.4 v0.5.4 第二轮修复（用户反馈遗留问题）

#### 问题 1 - 表头穿透（根因彻底修复）

**根因**：第 2885 行 `[data-theme='dark'] .n-data-table .n-data-table-th` 用半透明 `rgba(196, 149, 106, 0.1)` 背景，特异性 (0,3,0) 与第一轮修复的 surface-2 相同，但 2885 行在文件后面胜出 → sticky 表头穿透下层。

**修复**：将 2885 行的半透明 rgba 改为 `var(--tea-surface-3)` 实色（#251D16），并追加更高特异性的选择器（`.n-data-table-thead .n-data-table-th`）确保覆盖。

#### 问题 2 - 底部行穿透（防御性覆盖）

**修复**：追加规则覆盖所有可能的 td 变体：
- `n-data-table-td--last-row`（最后一行）
- `n-data-table-tr--striped .n-data-table-td`（斑马纹行）
- `n-data-table-tr:hover .n-data-table-td`（hover 行）

并给表格容器自身（n-data-table / n-data-table-wrapper / n-data-table-base-table / -header / -body）都设置实色 `var(--tea-surface-2)` 背景，作为最后一道防线。

**修复**：

2. 深色模式下强制 `.quick-action-card / .today-stat-card` 用实色 `var(--tea-surface-3)`
3. 深色模式下强制 `.n-card / .n-card__content / .demo-data-card` 用实色 `var(--tea-surface-2)`（覆盖第 2808 行的 :root 白色）

## 九、v0.5.4 第三轮修复（弹窗与演示数据问题）

### 9.1 用户反馈

> 生成演示数据点击提示，生成失败: 插入商品 西湖龙井 失败: UNIQUE constraint failed: products.code
> 一键清空数据按钮点击没有反应
> 右上角的主题设置按钮点击无反应

### 9.2 根因分析

#### 问题 1 + 2：弹窗/抽屉不显示（modal/drawer display:none）

**根因**：n-overrides.css 第 2065-2084 行三条"防御性" CSS 规则基于错误的类名假设：

```css
/* 错误假设：modal 显示时会添加 n-modal--show 类 */
.n-drawer:not(.n-drawer--show),
.n-modal:not(.n-modal--show) {
  pointer-events: none !important;
  display: none !important;
}

.n-drawer-container:not(.n-drawer-container--show),
.n-modal-container:not(.n-modal-container--show) {
  opacity: 0 !important;
  visibility: hidden !important;
}

.n-drawer-mask:not(.n-drawer-mask--show),
.n-modal-mask:not(.n-modal-mask--show) {
  opacity: 0 !important;
  visibility: hidden !important;
  display: none !important;
}
```

**Playwright 实测验证**（点击"一键清空数据"按钮后 1 秒内连续 20 次采样）：

| 时间 (ms) | container className | container visibility | mask display | card display |
|----------|---------------------|---------------------|--------------|--------------|
| 0 | `n-modal-container` | hidden | null | null |
| 50 | `n-modal-container` | hidden | none | none |
| 100~950 | `n-modal-container` | hidden | none | none |

**结论**：container 从未添加 `n-modal-container--show` 类，但 `:not()` 选择器始终命中，强制 `display: none` 让 Naive UI 的 `fade-in-transition-enter-active` 过渡无法完成，modal 永远不可见。

**根因本质**：Naive UI 的 n-modal/n-drawer 在显示过程中**不会**通过添加 `--show` 后缀类来标记状态。`--show` 后缀类是错误假设。这三条规则导致 modal/drawer 一旦进入"显示过渡"就被 `display: none` 强制打断，从而永远不可见。

#### 问题 3：演示数据生成 UNIQUE 约束失败

**根因**：`src-tauri/src/commands/dev_data.rs` 中 `seed_demo_data` 命令对 `products` 表使用 `INSERT INTO`（非 `OR IGNORE`/`OR REPLACE`），而 `products.code` 字段有 UNIQUE 约束。当数据库已有 P001-P030 商品时，再次点击"生成演示数据"会触发 `UNIQUE constraint failed: products.code`。

用户期望"生成演示数据"按钮是幂等的：无论数据库当前状态如何，点击后都应该能成功生成完整的演示数据。

### 9.3 修复方案

#### 修复 1：移除错误的 CSS 规则（n-overrides.css）

### 9.6 风险评估

#### 风险 1：移除 CSS 规则可能导致蒙层残留

**评估**：低风险。Naive UI 内部 transition 机制会自动处理关闭后的清理。原规则是基于错误假设添加的过度防御，移除后让 Naive UI 自己管理显隐即可。

**回滚**：如出现问题，可恢复三条规则（但需改用正确的类名判断，如 `:not(.n-modal--active)` 或基于 `display` 状态）。

#### 风险 2：seed_demo_data 清空已有数据

**评估**：可接受。这是"演示数据"按钮的预期语义——重新生成演示数据。用户真实数据不应依赖此按钮。

**回滚**：如需保留旧数据并 append，可将 `INSERT INTO products` 改为 `INSERT OR IGNORE INTO products`（但销售单等仍可能因外键失败）。当前方案更彻底。
