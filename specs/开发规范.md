# 开发规范 - 管用GL

---

## 一、代码风格规范

### 1.1 通用规则

| 规则 | 配置 |
|------|------|
| 缩进 | TypeScript/TSX/CSS: 2空格，Rust: 4空格 |
| 引号 | 单引号 |
| 分号 | 不使用分号 |
| 行尾逗号 | 尾随逗号（all） |
| 行宽 | 100字符 |
| 行尾 | LF |
| 编码 | UTF-8 |

### 1.2 命名约定

| 类型 | 规范 | 示例 |
|------|------|------|
| 前端目录名 | kebab-case | `form-designer/` |
| React 组件文件 | PascalCase.tsx | `FormCanvas.tsx` |
| Hook 文件 | useXxx.ts | `useAuth.ts` |
| 工具/服务文件 | camelCase.ts | `format.ts` |
| 样式文件 | kebab-case.css | `ant-overrides.css` |
| TypeScript 类型 | PascalCase | `Product`、`SaleOrder` |
| 变量/函数 | camelCase | `getUserList` |
| 常量 | UPPER_SNAKE_CASE | `MAX_RETRY_COUNT` |
| Rust 模块文件 | snake_case.rs | `warehouse_ops.rs` |
| Rust 函数名 | snake_case | `get_products` |
| Rust 结构体 | PascalCase | `SaleOrder` |

### 1.3 注释规范

**文件头注释（强制）**：
- TypeScript/TSX：`/** @file 简短中文描述 */`
- Rust：`//! 简短中文描述`

**函数/组件注释（推荐）**：
- 导出的函数/组件必须添加
- 业务逻辑复杂的函数必须添加

**行内注释（按需）**：
- 解释"为什么"而非"做了什么"
- 临时方案、兼容处理、特殊边界必须加

**豁免文件**：`*.d.ts`、`*.css`、`*.json`、自动生成的文件

## 二、Git 规范

### 2.1 分支命名

| 类型 | 格式 | 示例 |
|------|------|------|
| 功能 | feature/{功能名} | feature/product-management |
| 修复 | fix/{问题描述} | fix/login-error |
| 重构 | refactor/{重构内容} | refactor/api-service |
| 发布 | release/{版本号} | release/v0.7.0 |

### 2.2 提交信息

格式：`<type>(<scope>): <subject>`

| 类型 | 说明 |
|------|------|
| feat | 新功能 |
| fix | 修复bug |
| docs | 文档更新 |
| style | 代码格式（不影响逻辑） |
| refactor | 重构 |
| test | 测试 |
| chore | 构建/工具/配置 |
| perf | 性能优化 |

示例：
- `feat(products): 添加商品管理页面`
- `fix(auth): 修复登录状态丢失问题`
- `chore(deps): 升级antd到5.22.0`
- `feat(module): 新增业务模块`

## 三、API 规范

### 3.1 Tauri Command 规范

- 命令名：snake_case，如 `get_products`、`create_sale_order`
- 参数：使用结构体传参，避免过多独立参数
- 返回值：统一使用 `Result<T, AppError>`

### 3.2 HTTP RPC 规范（服务端）

- RESTful 风格
- 路径：`/api/{模块}/{操作}`
- 响应格式：`{ "code": 200, "message": "success", "data": {} }`

## 四、数据库规范

### 4.1 表命名

- 表名：snake_case，如 `sale_orders`、`product_specs`
- 字段名：snake_case，如 `created_at`、`order_id`
- 索引名：`idx_{表名}_{字段名}`

### 4.2 迁移规范

- 在 `database.rs` 中按版本号递增迁移
- 每次迁移必须可回滚
- 迁移版本号与项目版本号对应

---

## 五、前端开发规范

### 5.1 组件规范

- 每个页面一个目录，包含 `index.tsx`
- 复杂页面可包含 `components/` 子目录和 `hooks/` 子目录
- 组件使用函数式组件 + Hooks
- Props 使用 TypeScript interface 定义

### 5.2 状态管理规范

- 全局状态：Zustand Store（`stores/`）
- 页面局部状态：useState / useReducer
- 服务端状态：直接调用 Tauri Command

### 5.3 样式规范

- 优先使用 TailwindCSS 工具类
- 复杂样式使用 CSS Modules 或全局 CSS
- Ant Design 样式覆盖统一在 `ant-overrides.css`
- CSS 变量定义在 `variables.css`

---

## 六、Rust 开发规范

### 6.1 模块规范

- 每个业务模块一个 `.rs` 文件
- 模块在 `lib.rs` 中声明和注册
- 公共类型定义在 `models.rs`
- 错误处理使用 `error_util.rs` 中的工具

### 6.2 数据库操作规范

- 使用 `rusqlite` 手写 SQL
- 查询结果映射到 `models.rs` 中的结构体
- 事务操作使用 `connection.execute_batch()`

## 七、AI 交互协议

### 7.1 Prompt 规范

- 明确描述目标和上下文
- 指定涉及的文件路径
- 说明期望的输出格式

### 7.2 迭代流程

1. 提出需求
2. AI 生成初版
3. 人工审查反馈
4. AI 优化调整
5. 确认定稿
