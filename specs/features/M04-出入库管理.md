## 一、功能概述

出入库管理是茶叶店日常运营的核心业务环节，覆盖从采购入库到退货出库的全流程库存变动场景。本模块需支持**4 种出入库单据类型**（采购入库、报损出库、盘点调整、退货出库）以及**供应商档案管理**。

### 1.1 核心价值

- **流程闭环**：所有库存变动都有单据可追溯
- **批次管理**：每笔入库生成独立批次，支持成本核算和保质期管理
- **供应商协同**：建立供应商档案，跟踪进货来源
- **数据准确**：盘点 + 调整保证账实相符

## 三、功能需求

### 3.1 退货出库单（v0.2.0 新增）

**业务场景**：
- 茶叶验收后发现质量问题，联系供应商退货
- 进货数量超出实际需求，协商退货
- 临近保质期，供应商同意回收

**功能点**：

| 功能 | 说明 |
|------|------|
| 退货单列表 | 按日期范围、退货原因、供应商筛选 |
| 新增退货单 | 选择供应商 → 添加商品 → 选择单位 → 输入数量 → 选择原批次 → 填写退货原因 → 保存 |
| 退货单详情 | 查看完整退货明细 |
| 退货单打印 | V1.0 占位，V1.1 接入打印模板 |

**表单字段**：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| 退货日期 | 日期 | ✅ | 默认为今天 |
| 供应商 | 下拉选择 | ✅ | 来自供应商档案 |
| 退货原因 | 下拉 | ✅ | 质量问题/数量超出/保质期/其他 |
| 备注 | 文本 | 否 | 详细说明 |
| 商品明细 | 动态列表 | ✅ | 至少 1 条 |

**商品明细子表单**：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| 商品 | 下拉选择 | ✅ | 来自商品档案 |
| 销售单位 | 下拉选择 | ✅ | 该商品的销售单位 |
| 退货数量 | 数字 | ✅ | > 0 |
| 原批次 | 下拉选择 | ✅ | 该商品的可用批次（FIFO 排序） |
| 退货单价 | 金额 | ✅ | 默认 = 该批次采购价 |
| 小计 | 计算 | - | 数量 × 单价 |

**业务规则**：

```
退货克数 = 销售单位换算系数 × 退货数量
校验：原批次剩余克数 >= 退货克数
扣减：products.stock_grams -= 退货克数
扣减：inventory_batches.remaining_grams -= 退货克数（指定批次）
记录：stock_flow（flow_type = 'return_out'，change_grams = -退货克数）
```

## 六、技术实现要点

### 6.1 退货出库事务流程

```rust
pub async fn create_return_order(
    db: State<'_, Database>,
    input: ReturnOrderInput,
) -> Result<ReturnOrder, String> {
    let conn = db.get_conn()?;
    let now = Local::now().format("%Y-%m-%d %H:%M:%S").to_string();
    let order_id = Uuid::new_v4().to_string();
    
    // 开启排他事务
    conn.execute("BEGIN EXCLUSIVE TRANSACTION", [])?;
    
    // 1. 校验供应商
    let supplier_exists: i64 = conn.query_row(
        "SELECT COUNT(*) FROM suppliers WHERE id = ? AND is_active = 1",
        [&input.supplier_id], |row| row.get(0)
    )?;
    if supplier_exists == 0 {
        return Err("供应商不存在或已停用".to_string());
    }
    
    let mut total_amount = 0.0;
    let mut items = Vec::new();
    
    for item in &input.items {
        // 2. 查询原批次剩余克数
        let (product_name, unit_name, remaining, purchase_price): 
            (String, String, i64, f64) = conn.query_row(
            "SELECT p.name, su.name, b.remaining_grams, b.purchase_price
             FROM inventory_batches b
             JOIN products p ON p.id = b.product_id
             JOIN sales_units su ON su.id = ? AND su.product_id = b.product_id
             WHERE b.id = ?",
            params![item.unit_id, item.batch_id],
            |row| Ok((row.get(0)?, row.get(1)?, row.get(2)?, row.get(3)?))
        )?;
        
        // 3. 查询换算关系
        let conversion: i64 = conn.query_row(
            "SELECT conversion_to_base FROM sales_units WHERE id = ?",
            [&item.unit_id], |row| row.get(0)
        )?;
        
        let grams = conversion * item.quantity;
        
        // 4. 校验库存
        if remaining < grams {
            return Err(format!("批次[{}]剩余{}g，退货需要{}g", product_name, remaining, grams));
        }
        
        // 5. 扣减批次
        conn.execute(
            "UPDATE inventory_batches SET remaining_grams = remaining_grams - ? WHERE id = ?",
            params![grams, item.batch_id]
        )?;
        
        // 6. 扣减商品总库存
        conn.execute(
            "UPDATE products SET stock_grams = stock_grams - ? WHERE id = ?",
            params![grams, item.product_id]
        )?;
        
        // 7. 记录流水
        let new_balance: i64 = conn.query_row(
            "SELECT stock_grams FROM products WHERE id = ?",
            [&item.product_id], |row| row.get(0)
        )?;
        let flow_id = Uuid::new_v4().to_string();
        conn.execute(
            "INSERT INTO stock_flow (id, product_id, batch_id, flow_type, change_grams, balance_grams, order_id, created_at)
             VALUES (?, ?, ?, 'return_out', ?, ?, ?, ?)",
            params![flow_id, item.product_id, item.batch_id, -grams, new_balance, order_id, now]
        )?;
        
        let subtotal = purchase_price * item.quantity as f64;
        total_amount += subtotal;
        
        // 8. 保存退货明细
        let item_id = Uuid::new_v4().to_string();
        conn.execute(
            "INSERT INTO return_items (id, order_id, product_id, product_name, unit_id, unit_name, batch_id, quantity, unit_price, grams, subtotal)
             VALUES (?, ?, ?, ?, ?, ?, ?, ?, ?, ?, ?)",
            params![item_id, order_id, item.product_id, product_name, item.unit_id, unit_name, item.batch_id, item.quantity, purchase_price, grams, subtotal]
        )?;
        
        items.push(ReturnOrderItem { ... });
    }
    
    // 9. 创建退货单
    let order_no = format!("TH{}", Local::now().format("%Y%m%d%H%M%S"));
    conn.execute(
        "INSERT INTO return_orders (id, order_no, supplier_id, return_date, return_reason, total_amount, remark, created_at)
         VALUES (?, ?, ?, ?, ?, ?, ?, ?)",
        params![order_id, order_no, input.supplier_id, input.return_date, input.return_reason, total_amount, input.remark, now]
    )?;
    
    conn.execute("COMMIT", [])?;
    Ok(...)
}
```

### 6.2 数据库迁移（v0.1.0 → v0.2.0）

```rust
// SCHEMA_VERSION 从 1 递增到 2
fn run_migrations(conn: &Connection) -> SqliteResult<()> {
    let current_version: u32 = conn.pragma_query_value(None, "user_version", |row| row.get(0))?;
    
    if current_version < 1 {
        v1_initial_schema(conn)?;
    }
    if current_version < 2 {
        v2_suppliers_and_return(conn)?;
    }
    
    conn.pragma_update(None, "user_version", 2)?;
    Ok(())
}

fn v2_suppliers_and_return(conn: &Connection) -> SqliteResult<()> {
    conn.execute("CREATE TABLE IF NOT EXISTS suppliers ( ... )", [])?;
    conn.execute("CREATE TABLE IF NOT EXISTS return_orders ( ... )", [])?;
    conn.execute("CREATE TABLE IF NOT EXISTS return_items ( ... )", [])?;
    
    // 添加默认供应商（防止历史数据无法迁移）
    conn.execute(
        "INSERT OR IGNORE INTO suppliers (id, name) VALUES ('sup-default', '默认供应商')",
        []
    )?;
    
    // 兼容历史：purchase_orders.supplier_id 为空的补默认值
    conn.execute(
        "UPDATE purchase_orders SET supplier_id = 'sup-default' WHERE supplier_id IS NULL OR supplier_id = ''",
        []
    )?;
    Ok(())
}
```

## 七、风险与决策

| 风险 | 决策 | 理由 |
|------|------|------|
| 采购入库单 `supplier_id` 改为 NOT NULL | 数据迁移补默认供应商 "默认供应商" | 避免破坏历史数据 |
| 退货批次指定 | 强制要求选择原批次 | 精确追溯每笔退货的原始成本 |
| 退货是否生成应收/应付账款 | v0.2.0 不做，v0.3.0 规划 | 财务模块独立，超出本版本范围 |
| 供应商删除策略 | 软删除 + 有进货记录禁止删除 | 保留历史可追溯性 |
