## 一、设计目标

将 v0.2.0 时期不完整保存的 `purchase_in` Command 重构为**完整事务流程**，确保：
- 采购主单持久化（`purchase_orders`）
- 采购明细持久化（`purchase_items`）
- 历史单据可查询、可筛选、可详情查看
- 数据库 schema 升级到 v3，向后兼容 v0.2.0 数据

### 3.1 新增表 SQL

#### 3.1.1 `purchase_orders` 表

```sql
CREATE TABLE IF NOT EXISTS purchase_orders (
    id TEXT PRIMARY KEY NOT NULL,
    order_no TEXT NOT NULL UNIQUE,
    supplier_id TEXT NOT NULL,
    handler TEXT,
    total_amount REAL NOT NULL DEFAULT 0,
    payment_status TEXT NOT NULL DEFAULT 'unpaid'
        CHECK (payment_status IN ('unpaid', 'partial', 'paid')),
    remark TEXT NOT NULL DEFAULT '',
    created_at TEXT NOT NULL DEFAULT (datetime('now')),
    FOREIGN KEY (supplier_id) REFERENCES suppliers(id) ON DELETE RESTRICT
);

CREATE UNIQUE INDEX IF NOT EXISTS idx_purchase_order_no ON purchase_orders(order_no);
CREATE INDEX IF NOT EXISTS idx_purchase_supplier ON purchase_orders(supplier_id);
CREATE INDEX IF NOT EXISTS idx_purchase_date ON purchase_orders(created_at);
CREATE INDEX IF NOT EXISTS idx_purchase_payment_status ON purchase_orders(payment_status);
```

### 3.2 数据库迁移

**v0.2.0 (user_version=2) → v0.3.0 (user_version=3)**

```rust
// schema.rs 新增函数
pub fn migrate_v3_purchase_orders(conn: &Connection) -> SqliteResult<()> {
    // 1. 创建 purchase_orders 表
    conn.execute(
        "CREATE TABLE IF NOT EXISTS purchase_orders (
            id TEXT PRIMARY KEY NOT NULL,
            order_no TEXT NOT NULL UNIQUE,
            supplier_id TEXT NOT NULL,
            handler TEXT,
            total_amount REAL NOT NULL DEFAULT 0,
            payment_status TEXT NOT NULL DEFAULT 'unpaid'
                CHECK (payment_status IN ('unpaid', 'partial', 'paid')),
            remark TEXT NOT NULL DEFAULT '',
            created_at TEXT NOT NULL DEFAULT (datetime('now')),
            FOREIGN KEY (supplier_id) REFERENCES suppliers(id) ON DELETE RESTRICT
        )",
        [],
    )?;
    
    // 创建索引
    conn.execute("CREATE UNIQUE INDEX IF NOT EXISTS idx_purchase_order_no ON purchase_orders(order_no)", [])?;
    conn.execute("CREATE INDEX IF NOT EXISTS idx_purchase_supplier ON purchase_orders(supplier_id)", [])?;
    conn.execute("CREATE INDEX IF NOT EXISTS idx_purchase_date ON purchase_orders(created_at)", [])?;
    conn.execute("CREATE INDEX IF NOT EXISTS idx_purchase_payment_status ON purchase_orders(payment_status)", [])?;
    
    // 2. 创建 purchase_items 表
    conn.execute(
        "CREATE TABLE IF NOT EXISTS purchase_items (
            id TEXT PRIMARY KEY NOT NULL,
            order_id TEXT NOT NULL,
            product_id TEXT NOT NULL,
            product_name TEXT NOT NULL,
            unit_id TEXT NOT NULL,
            unit_name TEXT NOT NULL,
            quantity INTEGER NOT NULL,
            grams INTEGER NOT NULL,
            unit_price REAL NOT NULL,
            subtotal REAL NOT NULL,
            batch_id TEXT NOT NULL,
            batch_code TEXT NOT NULL,
            created_at TEXT NOT NULL DEFAULT (datetime('now')),
            FOREIGN KEY (order_id) REFERENCES purchase_orders(id) ON DELETE CASCADE,
            FOREIGN KEY (product_id) REFERENCES products(id) ON DELETE RESTRICT,
            FOREIGN KEY (unit_id) REFERENCES sales_units(id) ON DELETE RESTRICT,
            FOREIGN KEY (batch_id) REFERENCES inventory_batches(id) ON DELETE RESTRICT
        )",
        [],
    )?;
    
    conn.execute("CREATE INDEX IF NOT EXISTS idx_purchase_item_order ON purchase_items(order_id)", [])?;
    
    Ok(())
}
```

**在 `run_migrations` 中注册**：

```rust
const SCHEMA_VERSION: u32 = 3;  // 2 → 3

pub fn run_migrations(conn: &Connection) -> SqliteResult<()> {
    let current_version: u32 = conn.pragma_query_value(None, "user_version", |row| row.get(0))?;
    
    if current_version < 1 {
        create_tables(conn)?;
    }
    if current_version < 2 {
        migrate_v2_suppliers_and_return(conn)?;
    }
    if current_version < 3 {
        migrate_v3_purchase_orders(conn)?;  // 新增
    }
    
    if current_version < SCHEMA_VERSION {
        create_composite_indexes(conn)?;
        conn.pragma_update(None, "user_version", SCHEMA_VERSION)?;
    }
    
    Ok(())
}
```

### 3.3 数据迁移策略

| 数据 | 处理方式 |
|------|----------|
| v0.2.0 时期的 `inventory_batches`（含 `supplier_id`） | **不回填**到 `purchase_orders`，原因：缺乏完整的主单信息（handler、payment_status、remark 等） |
| v0.2.0 时期的 `stock_flow`（`flow_type='purchase_in'`） | 保留，仅用于流水追溯，不创建对应主单 |
| 新的采购入库（v0.3.0+） | 完整记录到 `purchase_orders` + `purchase_items` |

**理由**：避免数据错误。已存在批次是「事实数据」（实际库存增加），但不等于有「合规采购单」。

### 3.4 回滚策略

- **迁移失败时**：使用 SQLite 事务保证原子性，失败则完全不创建新表
- **回滚版本**：将 `user_version` 回退到 2
- **数据安全**：不删除任何 v0.2.0 已有数据

### 4.1 修改 `purchase_in` Command

**当前问题**：仅写 `inventory_batches` / `stock_flow`，未写主单

**改造方案**：

```rust
#[tauri::command]
pub async fn purchase_in(
    db: tauri::State<'_, Database>,
    input: PurchaseInput,
) -> Result<PurchaseOrder, String> {
    // 1. 校验输入
    if input.items.is_empty() {
        return Err("入库明细不能为空".to_string());
    }
    if input.supplier_id.is_none() {
        return Err("请选择供应商".to_string());
    }
    let supplier_id = input.supplier_id.as_ref().unwrap();
    
    let conn = db.get_conn()?;
    let now = Local::now().format("%Y-%m-%d %H:%M:%S").to_string();
    let order_id = Uuid::new_v4().to_string();
    let ts = Local::now();
    let order_no = format!("RK{}{:03}", ts.format("%Y%m%d%H%M%S"), (ts.timestamp_millis() % 1000) as u16);
    
    // 2. 排他事务
    conn.execute("BEGIN EXCLUSIVE TRANSACTION", [])
        .map_err(|e| e.to_string())?;
    
    let rollback = |e: String, conn: &Connection| -> String {
        let _ = conn.execute("ROLLBACK", []);
        e
    };
    
    // 3. 校验供应商存在且启用
    let supplier_exists: i64 = conn.query_row(
        "SELECT COUNT(*) FROM suppliers WHERE id = ? AND is_active = 1",
        [supplier_id],
        |row| row.get(0),
    ).map_err(|e| rollback(format!("查询供应商失败: {}", e), &conn))?;
    
    if supplier_exists == 0 {
        return Err(rollback("供应商不存在或已停用".to_string(), &conn));
    }
    
    let mut total_amount = 0.0;
    let mut items = Vec::new();
    
    // 4. 遍历明细
    for item in &input.items {
        // 4.1 查询商品信息
        let (product_name, product_type): (String, String) = conn.query_row(
            "SELECT name, product_type FROM products WHERE id = ?",
            [&item.product_id],
            |row| Ok((row.get(0)?, row.get(1)?)),
        ).map_err(|e| rollback(format!("商品不存在: {}", e), &conn))?;
        
        // 4.2 查询单位换算 + 单位名称
        let (unit_name, conversion): (String, i64) = conn.query_row(
            "SELECT name, conversion_to_base FROM sales_units WHERE id = ?",
            [&item.unit_id],
            |row| Ok((row.get(0)?, row.get(1)?)),
        ).map_err(|e| rollback(format!("单位不存在: {}", e), &conn))?;
        
        // 4.3 计算克数和小计
        let grams = item.quantity * conversion;
        let subtotal = item.unit_price * item.quantity as f64;
        total_amount += subtotal;
        
        // 4.4 生成批次号（UUID 8位避免冲突）
        let batch_id = Uuid::new_v4().to_string();
        let batch_code = format!("RK{}{}", Local::now().format("%Y%m%d"), &batch_id[..8]);
        
        // 4.5 插入批次记录
        conn.execute(
            "INSERT INTO inventory_batches (id, product_id, batch_code, purchase_price, 
             total_grams, remaining_grams, supplier_id, created_at)
             VALUES (?, ?, ?, ?, ?, ?, ?, ?)",
            params![
                batch_id, item.product_id, batch_code,
                item.unit_price, grams, grams,
                supplier_id, now
            ],
        ).map_err(|e| rollback(format!("插入批次失败: {}", e), &conn))?;
        
        // 4.6 更新商品库存
        let stock_field = if product_type == "weight" { "stock_grams" } else { "stock_units" };
        conn.execute(
            &format!("UPDATE products SET {} = {} + ? WHERE id = ?", stock_field, stock_field),
            params![grams, item.product_id],
        ).map_err(|e| rollback(format!("更新库存失败: {}", e), &conn))?;
        
        // 4.7 记录流水
        let new_balance: i64 = conn.query_row(
            &format!("SELECT {} FROM products WHERE id = ?", stock_field),
            [&item.product_id],
            |row| row.get(0),
        ).map_err(|e| rollback(format!("查询结余失败: {}", e), &conn))?;
        
        let flow_id = Uuid::new_v4().to_string();
        conn.execute(
            "INSERT INTO stock_flow (id, product_id, batch_id, flow_type, change_grams, 
             balance_grams, order_id, created_at)
             VALUES (?, ?, ?, ?, ?, ?, ?, ?)",
            params![
                flow_id, item.product_id, batch_id,
                "purchase_in", grams, new_balance, order_id, now
            ],
        ).map_err(|e| rollback(format!("记录流水失败: {}", e), &conn))?;
        
        // 4.8 ✨ 新增：插入 purchase_items 明细
        let item_id = Uuid::new_v4().to_string();
        conn.execute(
            "INSERT INTO purchase_items
                (id, order_id, product_id, product_name, unit_id, unit_name,
                 quantity, grams, unit_price, subtotal, batch_id, batch_code, created_at)
             VALUES (?, ?, ?, ?, ?, ?, ?, ?, ?, ?, ?, ?, ?)",
            params![
                item_id, order_id, item.product_id, product_name,
                item.unit_id, unit_name,
                item.quantity, grams, item.unit_price, subtotal,
                batch_id, batch_code, now
            ],
        ).map_err(|e| rollback(format!("插入明细失败: {}", e), &conn))?;
        
        items.push(PurchaseOrderItem {
            product_id: item.product_id.clone(),
            product_name,
            unit_name,
            quantity: item.quantity,
            grams,
            unit_price: item.unit_price,
            subtotal,
            batch_id,
            batch_code,
        });
    }
    
    // 5. ✨ 新增：插入 purchase_orders 主单
    let payment_status = input.payment_status.as_deref().unwrap_or("unpaid");
    conn.execute(
        "INSERT INTO purchase_orders
            (id, order_no, supplier_id, handler, total_amount, payment_status, remark, created_at)
         VALUES (?, ?, ?, ?, ?, ?, ?, ?)",
        params![
            order_id, order_no, supplier_id, input.handler,
            total_amount, payment_status,
            input.remark.clone().unwrap_or_default(), now
        ],
    ).map_err(|e| rollback(format!("创建主单失败: {}", e), &conn))?;
    
    // 6. 提交
    conn.execute("COMMIT", []).map_err(|e| e.to_string())?;
    
    Ok(PurchaseOrder {
        id: order_id,
        order_no,
        supplier_id: supplier_id.to_string(),
        handler: input.handler,
        total_amount,
        remark: input.remark,
        items,
        created_at: now,
    })
}
```

SELECT

    po.handler, po.total_amount, po.payment_status, po.remark, po.created_at,
    COUNT(pi.id) AS item_count

LEFT JOIN suppliers s ON s.id = po.supplier_id
LEFT JOIN purchase_items pi ON pi.order_id = po.id

## 七、并发控制

### 7.1 事务隔离级别

`purchase_in` 使用 `BEGIN EXCLUSIVE TRANSACTION`（同 `create_return_order`），原因：
- 防止两个采购单同时插入相同批次号（虽然用了 UUID 8 位，但保险起见）
- 防止库存更新与流水记录的竞态
- 防止主单与明细插入的不一致

## 十、技术决策说明

### 10.1 为什么 `purchase_in` 重构而不是新增 Command？

| 方案 | 优点 | 缺点 | 选择 |
|------|------|------|------|
| A：重构 `purchase_in` | 单点维护，保持 API 兼容 | 函数变长 | ✅ |
| B：新增 `create_purchase_order` | 职责更清晰 | 老 API 仍存在不完整数据风险 | ❌ |

### 10.2 为什么 v0.2.0 历史数据不回填？

| 方案 | 优点 | 缺点 | 选择 |
|------|------|------|------|
| A：回填 | 数据完整 | 缺少 handler、payment_status、remark，会产生大量错误数据 | ❌ |
| B：不回填 | 数据准确 | v0.3.0 前无主单（但有库存和批次） | ✅ |

### 10.3 付款状态字段类型

| 方案 | 优点 | 缺点 | 选择 |
|------|------|------|------|
| A：TEXT + CHECK 约束 | 简单 | 错误数据可绕过 CHECK | 当前 |
| B：ENUM 类型 | 类型安全 | SQLite 不原生支持 | ❌ |
| C：关联表 | 灵活 | 过度设计 | ❌ |

**当前选择 A**，通过 `CHECK (payment_status IN ('unpaid', 'partial', 'paid'))` 保证数据合法性。
