## 二、项 1：侧栏树状分组连线

### 2.1 实现方案

#### 原理
- 利用 CSS 伪元素 `::after` 在每个 `.tea-sider-group` 容器内画一条 dashed 竖线
- 竖线位置：固定 left + 跨越子项列表区域（跳过分组标题）
- 折叠态不显示（用选择器排除）

#### CSS 实现

```scss
/* 展开态：分组容器相对定位 */
.tea-sider:not(.tea-sider-collapsed) .tea-sider-group {
  position: relative;
}

/* 展开态：分组内的子项列表画虚线 */
.tea-sider:not(.tea-sider-collapsed) .tea-sider-group::after {
  content: '';
  position: absolute;
  left: 16px;              // 距离侧栏左边 16px（与 menu padding 8 + 8 对齐）
  top: 30px;               // 跳过分组标题（约 28-30px 高度）
  bottom: 4px;
  width: 1px;
  border-left: 1px dashed var(--tea-primary);
  opacity: 0.3;            // 30% 透明度
  pointer-events: none;    // 不拦截鼠标事件
  z-index: 0;
  transition: opacity var(--tea-transition-normal),
              border-color var(--tea-transition-normal);
}

/* 深色模式适配 */
[data-theme='dark'] .tea-sider:not(.tea-sider-collapsed) .tea-sider-group::after {
  opacity: 0.45;           // 深色背景下提高透明度
}
```

#### 与现有激活竖条的关系
- 现有分组激活竖条：在 `.tea-sider-section`（分组标题）的 `::before`
- 新增连线：在 `.tea-sider-group`（分组容器）的 `::after`
- **完全不同的元素和位置，互不冲突**

#### 为什么不改 sidebarMenus.ts
- 改动只影响 CSS，无需改 TS 数据层
- 保持单一职责（菜单配置在 .ts，样式在 .vue）

### 2.2 关键技术点

#### 竖线位置计算
```
侧栏宽度 220px
├── padding 8px (tea-sider-menu 的 padding: 4px 0 12px + 其他)
├── 分组 1
│   ├── 分组标题 (高约 28px)
│   ├── 菜单项 1 (高约 36px)
│   ├── 菜单项 2
│   └── ...
├── 分组 2
...
```
- 竖线 `left: 16px` = 距侧栏左边缘 16px
- 竖线 `top: 30px` = 跳过分组标题
- 竖线 `bottom: 4px` = 不画到分组底部

#### 主色变量
- 使用 `var(--tea-primary)` 而非硬编码 #C4956A
- 切主色时连线颜色自动跟随

#### 深色模式
- 浅色模式：opacity 0.3（细而隐）
- 深色模式：opacity 0.45（提高对比度）
- 透明度的变化而非颜色变化，保持简洁

```typescript
// localStorage 键
const STORAGE_KEY_USERNAME = 'tea-last-username'
const STORAGE_KEY_REMEMBER = 'tea-remember'
const STORAGE_KEY_PASSWORD = 'tea-last-password'

/**
 * base64 编码（仅本地防明文，非加密）
 */
function encodeBase64(str: string): string {
  try {
    return btoa(unescape(encodeURIComponent(str)))
  } catch {
    return ''
  }
}

function decodeBase64(str: string): string {
  try {
    return decodeURIComponent(escape(atob(str)))
  } catch {
    return ''
  }
}

/**
 * 加载记住的登录信息
 */
function loadRememberedLogin(): { username: string; password: string; remember: boolean } {
  try {
    const remember = localStorage.getItem(STORAGE_KEY_REMEMBER) === 'true'
    const username = localStorage.getItem(STORAGE_KEY_USERNAME) || ''
    const password = remember
      ? decodeBase64(localStorage.getItem(STORAGE_KEY_PASSWORD) || '')
      : ''
    return { username, password, remember }
  } catch {
    return { username: '', password: '', remember: false }
  }
}

/**
 * 保存登录信息
 */
function saveRememberedLogin(username: string, password: string, remember: boolean) {
  try {
    if (remember && username) {
      localStorage.setItem(STORAGE_KEY_REMEMBER, 'true')
      localStorage.setItem(STORAGE_KEY_USERNAME, username)
      localStorage.setItem(STORAGE_KEY_PASSWORD, encodeBase64(password))
    } else {
      localStorage.setItem(STORAGE_KEY_REMEMBER, 'false')
      localStorage.setItem(STORAGE_KEY_USERNAME, username)
      localStorage.removeItem(STORAGE_KEY_PASSWORD)
    }
  } catch {
    /* 忽略（quota / private mode） */
  }
}
```

**状态管理**：

```

**onMounted 替换硬编码**：

onMounted(() => {

async function handleLogin() {

  setTimeout(() => {

    router.push('/')
  }, 400)
}
```

### 3.3 关键技术点

#### base64 编码 vs 真加密
- 本地单机版无强安全需求
- base64 仅防"眼睛一扫看到明文"
- 比 JXC 的实现更简单（JXC 用 localStorage 明文）

#### localStorage 失败处理
- try/catch 包住（quota / private mode 可能抛错）
- 失败时静默，不影响登录流程

#### 主题切换对装饰层的影响
- 15 个光斑颜色：`var(--tea-login-dot-color)` 已经是 CSS 变量
- 极光：`var(--tea-login-aurora-1/2)` 已经是 CSS 变量
- 卡片背景：`var(--tea-card-bg)` 已经是 CSS 变量
- 切主题后所有装饰层自动跟随

#### 散点数据生成时机
- v0.5.0 在 `setup` 中通过 `computed` 生成（每次组件 mount 时随机）
- v0.5.1 保留同样逻辑（保持位置"看似随机但每次刷新会变"）
- 也可改为固定数组（保持位置"看起来随机但每次刷新一致"）
- **选择保持 computed 方案**：因为本地单机版，不要求 SSR 一致性

## 六、风险与缓解

| 风险 | 等级 | 缓解 |
|------|------|------|
| 侧栏竖线与菜单项点击冲突 | 🟢 低 | 伪元素 `pointer-events: none` |
| 深色模式竖线对比度不足 | 🟡 中 | 已规划深色模式 opacity 0.45 |
| 主题切换按钮遮挡关闭 X | 🟢 低 | 卡片无 X 按钮（NDrawer 才有，登录页无） |
| 15 个光斑动画耗电 | 🟢 低 | 透明度 + transform 动画，GPU 加速 |
| base64 误用为加密 | 🟢 低 | 函数命名明确"encode"非"encrypt" |
| localStorage 跨用户 | 🟡 中 | 本地单机版本就单用户，不做防护 |
