# M08 打印模板设计器 — 技术方案

> **版本**：v0.7.0（新功能模块，minor）
> **日期**：2026-07-13
> **前置**：v0.6.1
> **依赖**：无后端变更（模板存 localStorage，输出走现有 `window.print()`；原生 ESC/POS 驱动暂缓）

---

## 一、目标与范围

把现有"写死在 `utils/print.ts` 里、且打印模板页仅为占位壳"的打印能力，重构为**可配置、可预览、可持久化**的模板体系。

### 1.1 范围（已与用户确认）

| 项 | 决定 |
|----|------|
| 编辑器形态 | **结构化区块配置器**（非拖拽、非 HTML 源码） |
| 模板范围 | **小票 + 采购入库单 + 退货出库单 + 条码标签**，共 4 种 |
| 存储 | localStorage（不改动 SQLite，不动后端命令） |
| 输出 | 维持浏览器 `window.print()`（原生驱动本次不做） |

### 1.2 不在范围

- 原生 ESC/POS 热敏驱动、标签打印机指令（后续 v1.0 单独做）
- 后端模板表 / 多店模板同步
- SQLCipher 加密

## 二、数据模型（模板配置 JSON）

```ts
// types/printTemplate.ts
export type TemplateType = 'receipt' | 'purchase' | 'return' | 'label'

export type BlockKind =
  | 'header'      // 店名（大字）
  | 'shopInfo'    // 地址 / 电话
  | 'meta'        // 单号 / 日期 / 供应商 / 经手人（采购退货用）
  | 'items'       // 商品明细表
  | 'summary'     // 合计 / 优惠 / 实付（小票）；总计（采购退货）
  | 'member'      // 会员名 / 积分（小票）
  | 'customText'  // 自由文本行（如页脚感谢语、促销语）
  | 'barcode'     // Code128（标签）
  | 'qrcode'      // 二维码（标签）

export interface TemplateBlock {
  kind: BlockKind
  enabled: boolean
  title?: string            // 区块标题（可选）
  fontSize: number          // px，默认 12
  align: 'left' | 'center' | 'right'  // 默认 center（header）/ left（其余）
  text?: string             // customText 内容
  fields?: string[]         // 该区块可显示的子字段白名单
}

export interface PaperConfig {
  widthMm: number           // 小票 58/80；采购退货 210(A4)；标签 40/60
  heightMm?: number         // 标签专用（30/40）
}

export interface PrintTemplate {
  id: TemplateType
  name: string
  type: TemplateType
  paper: PaperConfig
  blocks: TemplateBlock[]   // 顺序即渲染顺序
  updatedAt: string
}
```

- 字段默认值以"覆盖现有写死 HTML"为准（如小票默认含 header/shopInfo/items/summary/member/customText 感谢语），保证**重构不回退现有打印效果**。
- 金额统一 `toFixed(2)` + 等宽（沿用现有纪律）。

## 三、存储与状态

新建 `stores/printTemplates.ts`（Pinia）：
- `templates: Ref<Record<TemplateType, PrintTemplate>>`
- `loadTemplates()`：首次从 localStorage 读取；无则注入 `defaultTemplates` 种子。
- `saveTemplate(t)` / `saveAll()`：写回 localStorage（key `tea-print-templates`）。
- `resetTemplate(type)`：恢复默认。
- 复用 `useSettingsStore().settings` 的 `shopName/address/phone`（店铺信息单一来源，不从模板里再存一份）。

> 不引入后端命令，符合"先完成界面设计"的阶段性定位，低风险。

## 五、渲染引擎（替换写死 HTML）

`utils/printTemplate.ts`：
- `renderTemplateHTML(tpl, data): string` —— 同步，生成完整 `<html>`（含 `@page { size: {widthMm}mm auto }`、字体、区块样式），遍历 `enabled` 区块按 `kind` 渲染：
  - header → 店名（读取 `data.shopName`）
  - shopInfo → 地址/电话（读取 `data`，按 `fields` 过滤）
  - meta → 单号/日期/供应商/经手人
  - items → 明细表（列由 `fields` 决定：名称/数量/单价/金额）
  - summary → 合计/优惠/实付 或 总计
  - member → 会员名/积分
  - customText → `text`（按行拆分）
- 金额 `.toFixed(2)`，等宽。
- 标签的条码在 `printLabel` 中异步生成 dataURL 后拼入（不进同步单测）。

`utils/print.ts` 改造：
- `printReceipt(order)` → 取 `templates.receipt` 渲染；
- 新增 `printPurchaseOrder(order)` / `printReturnOrder(order)` / `printLabel(product)` 走模板；
- 旧 `buildReceiptHTML` 等保留为 fallback（模板缺失时），但默认走模板。

## 九、优点 / 弊端 / 风险

| 维度 | 说明 |
|------|------|
| 优点 | 模板可配可存、所见即所得预览；不动后端、低风险；复用店铺设置；4 种单据统一体系；为后续原生打印/多店同步打好数据结构基础 |
| 弊端 | 结构化区块不如拖拽自由，极端个性化排版受限（茶叶店场景足够） |
| 风险(低) | localStorage 换机/清缓存会丢模板 → 缓解：提供「重置默认」+ 后续可迁后端表 |
| 风险(低) | 标签条码在打印 HTML 中需异步生成 dataURL，复杂单据略慢 → 缓解：仅标签用，数据量小 |
| 风险(中) | 采购/退货页加打印按钮需补其数据组装（现有页有详情数据，需对齐字段）→ 缓解：用现有详情接口数据构造，单测覆盖渲染 |
