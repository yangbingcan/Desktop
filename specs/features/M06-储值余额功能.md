## 二、背景与价值

### 2.1 业务背景

会员储值是茶叶店提升客户粘性、提前回笼资金的核心工具。会员预先充值一定金额到账户中，后续消费时可直接从余额扣款，避免每次都扫码支付的麻烦，同时店家也能锁定客户的未来消费。

M05 会员管理虽然已建立会员档案和消费记录，但储值功能尚未实现，会员无法充值、无法用余额支付、退款流程缺失。

### 2.2 目标用户

- **会员**：希望预存金额、便捷消费、享受会员服务的客户
- **店员**：需要快速完成充值、扣款、退款操作
- **店主**：希望提前回笼资金、锁定客户消费

### 2.3 使用场景

1. **新会员充值**：会员首次办卡时，店员引导充值（任意金额，无最低限制）
2. **老会员复购充值**：会员消费过程中感觉余额不足，主动充值
3. **收银台余额扣款**：会员消费时选择"余额支付"方式，输入扣款金额
4. **退款申请**：会员不再需要储值服务时申请退款，退剩余余额到原支付方式
5. **余额流水查询**：会员或店员查询历史充值/扣款/退款记录

### 2.4 业务价值

- **资金回笼**：商家提前获得现金流，提升经营稳定性
- **客户粘性**：储值会员复购率显著高于非储值会员
- **支付便捷**：余额扣款比现金/微信更快，提升收银效率
- **账目清晰**：完整的流水记录便于对账和审计

## 三、业务规则

### 3.1 充值规则

| 规则项 | 取值 | 说明 |
|--------|------|------|
| 充值金额 | 自由金额，无最低限制 | 店员在弹窗中输入任意金额 |
| 充值支付方式 | 现金 / 微信转账 / 支付宝转账 | v0.3.1 不集成支付 API，记录为转账方式 |
| 充值赠送 | 预留接口字段，v0.3.1 暂不启用 | 字段保留为 `bonus_amount`，未来扩展 |
| 充值时机 | 任意时刻 | 会员详情页"充值"按钮 |
| 充值操作人 | 登录店员 | 自动记录到流水 |
| 单笔无上限 | - | 由店员根据实际情况控制 |

### 3.2 扣款规则

| 规则项 | 取值 | 说明 |
|--------|------|------|
| 扣款触发 | 收银台"余额支付" | 收银员手动选择本次使用余额金额 |
| 单次扣款上限 | 不超过当前余额 | 余额不足时弹出友好提示 |
| 扣款不超额 | ✅ 严格校验 | 余额扣款后不能为负 |
| 扣款不产生积分 | ✅ 符合 M05 规则 | 储值扣款不计入积分 |
| 关联订单 | ✅ 记录 order_id | 用于审计和对账 |

### 3.3 退款规则

| 规则项 | 取值 | 说明 |
|--------|------|------|
| 退款入口 | 会员详情页"退款"按钮 | 店员操作 |
| 退款金额 | ≤ 剩余余额 | 可退任意金额（不超过剩余） |
| 退款方式 | 默认退到原支付方式 | 取该会员最近一次充值的支付方式 |
| 退款操作人 | 登录店员 | 自动记录 |
| 退款备注 | 必填 | 至少 5 个字符，说明退款原因 |
| 退款不收手续费 | ✅ v0.3.1 不收 | 预留 `fee_amount` 字段 |

### 3.4 流水规则

| 规则项 | 取值 | 说明 |
|--------|------|------|
| 流水类型 | recharge（充值）/ consume（扣款）/ refund（退款） | 三种类型 |
| 余额快照 | ✅ 记录 balance_after | 每次变动后写入当前余额 |
| 操作人 | ✅ 记录 operator | 用于审计 |
| 关联订单 | ✅ 扣款时记录 order_id | 充值/退款可为空 |
| 不可删除 | ✅ 仅追加 | 审计完整性 |
| 不可修改 | ✅ 历史记录 | 数据真实性 |

## 五、验收标准

### 5.1 会员充值（AC-R-01 ~ AC-R-04）

#### AC-R-01: 充值弹窗基本操作
- **Given**: 店员在会员详情页点击"充值"按钮
- **When**: 弹出充值对话框，店员输入金额（任意正数）、选择支付方式、填写备注（可选）
- **Then**:
  - 弹窗显示"充值"标题
  - 金额输入框接受正数（≥0.01），不接受负数和零
  - 支付方式下拉显示：现金 / 微信转账 / 支付宝转账
  - 默认支付方式为"现金"
  - "确认充值"按钮在金额有效时启用
- **验证方法**: 启动应用，进入会员详情页，测试充值弹窗

#### AC-R-02: 充值成功持久化
- **Given**: 会员当前余额 100 元
- **When**: 店员充值 200 元（现金），点击"确认充值"
- **Then**:
  - 会员 balance 字段从 100 → 300
  - `member_balance_logs` 表新增 1 条 recharge 类型流水
  - 流水 change_amount = 200
  - 流水 balance_after = 300
  - 流水 payment_method = "cash"
  - 流水 operator = 当前登录用户名
  - 弹窗自动关闭，会员详情页余额刷新为 300
  - 成功提示"充值成功"
- **验证方法**: 通过应用 UI 操作 + 数据库验证

#### AC-R-03: 充值金额校验
- **Given**: 充值弹窗已打开
- **When**: 店员输入无效金额（0、负数、空值、非数字）
- **Then**:
  - 输入框红色提示"金额必须大于 0"
  - "确认充值"按钮禁用
  - 不会写入数据库
- **验证方法**: 边界值测试

#### AC-R-04: 充值支付方式记录
- **Given**: 会员充值 100 元
- **When**: 选择"微信转账"作为支付方式
- **Then**:
  - 流水 payment_method 字段记录为 "wechat"
  - 退款时默认退到微信
- **验证方法**: 单元测试 + 集成测试

### 5.2 收银台余额扣款（AC-R-05 ~ AC-R-09）

#### AC-R-05: 收银台选择余额支付
- **Given**: 会员已识别，订单总额 150 元，会员余额 200 元
- **When**: 收银员选择支付方式为"余额支付"，输入扣款金额 150
- **Then**:
  - 弹窗提示"本次使用余额支付 150 元"
  - 订单应付金额 = 150 - 150 = 0
  - 确认后订单完成
  - 会员 balance 从 200 → 50
  - 流水记录扣款 150 元
- **验证方法**: 收银台端到端测试

#### AC-R-06: 余额不足提示
- **Given**: 会员余额 100 元，订单总额 150 元
- **When**: 收银员选择余额支付，输入 150
- **Then**:
  - 系统检测到余额不足（100 < 150）
  - 弹窗友好提示"余额不足，当前余额 100 元，最多可使用 100 元"
  - 输入框自动调整为 100
  - 收银员可继续选择其他支付方式补足 50 元
- **验证方法**: 边界值测试

#### AC-R-07: 余额与其他支付方式混用
- **Given**: 会员余额 100 元，订单总额 150 元
- **When**: 收银员选择余额支付 100 元 + 现金 50 元
- **Then**:
  - 订单正常完成
  - 会员 balance 扣减 100
  - 收银台记录两种支付方式
- **验证方法**: 混合支付测试

#### AC-R-08: 余额扣款不产生积分
- **Given**: 会员消费 100 元，全部用余额支付
- **When**: 订单完成
- **Then**:
  - 会员 points 字段不变（不增加积分）
  - 消费记录正确关联订单
- **验证方法**: 单元测试

#### AC-R-09: 扣款事务原子性
- **Given**: 会员余额 200 元，订单 150 元
- **When**: 扣款过程中数据库异常
- **Then**:
  - 会员 balance 字段不变（事务回滚）
  - 订单不创建
  - 流水不写入
- **验证方法**: 单元测试（事务回滚验证）

### 5.3 会员退款（AC-R-10 ~ AC-R-13）

#### AC-R-10: 退款弹窗基本操作
- **Given**: 店员在会员详情页点击"退款"按钮（仅在余额 > 0 时显示）
- **When**: 弹出退款对话框
- **Then**:
  - 弹窗显示"退款"标题
  - 显示当前余额
  - 默认退款方式为该会员最近一次充值的支付方式
  - 退款金额输入框默认为当前余额
  - 退款备注为必填（≥5 字符）
  - "确认退款"按钮在所有字段有效时启用
- **验证方法**: 启动应用，测试退款弹窗

#### AC-R-11: 退款成功持久化
- **Given**: 会员当前余额 200 元，最近一次充值为微信转账
- **When**: 店员退款 200 元，备注"会员申请退款"
- **Then**:
  - 会员 balance 字段从 200 → 0
  - `member_balance_logs` 表新增 1 条 refund 类型流水
  - 流水 change_amount = -200（负数）
  - 流水 balance_after = 0
  - 流水 payment_method = "wechat"
  - 流水 remark = "会员申请退款"
  - 弹窗自动关闭，会员详情页余额刷新为 0
  - 成功提示"退款成功"
- **验证方法**: 应用 UI + 数据库验证

#### AC-R-12: 退款金额校验
- **Given**: 会员余额 100 元
- **When**: 店员输入退款金额 150（超过余额）
- **Then**:
  - 输入框红色提示"退款金额不能超过余额 100 元"
  - "确认退款"按钮禁用
  - 不会写入数据库
- **验证方法**: 边界值测试

#### AC-R-13: 退款备注必填
- **Given**: 退款弹窗已打开
- **When**: 店员不填备注或备注 < 5 字符
- **Then**:
  - 备注输入框红色提示"退款原因至少 5 个字符"
  - "确认退款"按钮禁用
  - 不会写入数据库
- **验证方法**: 边界值测试

### 5.4 余额流水查询（AC-R-14 ~ AC-R-15）

#### AC-R-14: 流水列表显示
- **Given**: 会员有 5 条充值 + 3 条扣款 + 1 条退款记录
- **When**: 店员在会员详情页点击"储值流水"标签页
- **Then**:
  - 表格按时间倒序显示 9 条流水
  - 每行显示：变动类型（标签颜色）、变动金额（带正负号）、支付方式、变动后余额、操作人、备注、关联订单、时间
  - 充值（recharge）显示绿色"+"标签
  - 扣款（consume）显示橙色"-"标签
  - 退款（refund）显示红色"-"标签
- **验证方法**: UI 截图验证

#### AC-R-15: 流水筛选
- **Given**: 会员有 5 条充值 + 3 条扣款记录
- **When**: 店员筛选"仅看充值"
- **Then**:
  - 表格仅显示 5 条 recharge 类型流水
  - 筛选器显示当前筛选条件
  - 清除筛选后恢复全部
- **验证方法**: UI 交互测试

### 5.5 余额显示（AC-R-16）

#### AC-R-16: 多处显示余额
- **Given**: 会员余额 150 元
- **When**: 店员在以下位置查看会员信息
- **Then**:
  - 会员列表：余额列显示 "150.00"
  - 会员详情：基本信息卡片显示 "储值余额: ¥150.00"
  - 收银台识别会员后：顶部显示 "会员: 张三 余额: ¥150.00"
- **验证方法**: 跨页面一致性测试

## 六、功能流程

### 6.1 充值流程

```
店员在会员详情页点击"充值"
    ↓
弹出充值对话框（金额/支付方式/备注）
    ↓
店员输入金额（≥0.01）→ 选择支付方式 → 备注（可选）
    ↓
点击"确认充值"
    ↓
后端开启事务
    ↓
  ├─ 查询会员当前余额
  ├─ 计算新余额 = 当前余额 + 充值金额
  ├─ 更新 members.balance = 新余额
  └─ 插入 member_balance_logs (type=recharge, change_amount, balance_after, ...)
    ↓
提交事务
    ↓
返回新余额 + 流水
    ↓
前端刷新会员详情页余额
```

### 6.2 扣款流程（收银台）

```
收银员在收银台选择支付方式"余额"
    ↓
弹出金额输入框（默认订单总额，最多不超过会员余额）
    ↓
收银员输入或调整金额
    ↓
点击"确认支付"
    ↓
后端开启事务
    ↓
  ├─ 校验订单存在
  ├─ 查询会员当前余额
  ├─ 校验余额 ≥ 扣款金额（不足则报错）
  ├─ 计算新余额 = 当前余额 - 扣款金额
  ├─ 更新 members.balance = 新余额
  ├─ 创建/更新销售订单（payment_method 含 balance）
  └─ 插入 member_balance_logs (type=consume, change_amount=-X, order_id, ...)
    ↓
提交事务
    ↓
返回新余额 + 流水
    ↓
收银台显示支付成功
```

### 6.3 退款流程

```
店员在会员详情页点击"退款"（仅余额 > 0 时显示）
    ↓
弹出退款对话框（当前余额/退款金额/退款方式/备注）
    ↓
店员确认或调整退款金额（≤ 余额）
    ↓
查询该会员最近一次充值的支付方式 → 默认选中
    ↓
填写退款备注（≥5 字符）
    ↓
点击"确认退款"
    ↓
后端开启事务
    ↓
  ├─ 校验退款金额 > 0 且 ≤ 当前余额
  ├─ 计算新余额 = 当前余额 - 退款金额
  ├─ 更新 members.balance = 新余额
  └─ 插入 member_balance_logs (type=refund, change_amount=-X, payment_method, remark, ...)
    ↓
提交事务
    ↓
返回新余额 + 流水
    ↓
前端刷新会员详情页余额
```

### 6.4 异常处理

| 异常情况 | 处理方式 |
|---------|---------|
| 充值金额 ≤ 0 | 前端校验 + 后端校验双重保护 |
| 充值金额非数字 | 前端 input type=number 限制 |
| 扣款金额 > 余额 | 友好提示"余额不足"，按钮禁用 |
| 退款金额 > 余额 | 友好提示"退款金额不能超过余额" |
| 退款备注 < 5 字符 | 提示"退款原因至少 5 个字符" |
| 数据库操作失败 | 事务回滚 + 错误提示"操作失败，请重试" |
| 会员不存在 | 错误提示"会员不存在" |
| 会员已软删除 | 错误提示"会员已停用，无法操作" |
| 并发扣款 | 排他事务（EXCLUSIVE）防止超扣 |

## 七、数据需求

### 7.1 新增数据库表

#### `member_balance_logs`（会员储值流水表）

| 字段 | 类型 | 必填 | 默认值 | 说明 |
|------|------|------|--------|------|
| id | TEXT | ✅ | - | 主键 UUID |
| member_id | TEXT | ✅ | - | 会员 ID（外键 → members.id） |
| change_type | TEXT | ✅ | - | 变动类型：recharge（充值）/ consume（扣款）/ refund（退款） |
| change_amount | REAL | ✅ | - | 变动金额（扣款/退款为负数） |
| balance_after | REAL | ✅ | - | 变动后余额（用于审计） |
| payment_method | TEXT | ✅ | - | 支付方式：cash（现金）/ wechat（微信）/ alipay（支付宝） |
| operator | TEXT | ✅ | - | 操作人（店员用户名） |
| related_order_id | TEXT | ❌ | NULL | 关联订单 ID（扣款时必填） |
| bonus_amount | REAL | ❌ | 0 | 赠送金额（v0.3.1 预留字段，暂不启用） |
| fee_amount | REAL | ❌ | 0 | 手续费（v0.3.1 预留字段，暂不启用） |
| remark | TEXT | ❌ | '' | 备注 |
| created_at | TEXT | ✅ | datetime('now') | 创建时间 |

**索引**：
- `idx_balance_log_member` (member_id)
- `idx_balance_log_type` (change_type)
- `idx_balance_log_created` (created_at)
- `idx_balance_log_order` (related_order_id)

**外键约束**：
- `member_id` → `members(id)` ON DELETE RESTRICT
- `related_order_id` → `sales_orders(id)` ON DELETE SET NULL

**CHECK 约束**：
```sql
change_type IN ('recharge', 'consume', 'refund')
payment_method IN ('cash', 'wechat', 'alipay')
```
