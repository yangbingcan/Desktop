# 茶叶店管理系统 V2 大版本迭代规划

> **版本**: v2.0.0-alpha  
> **日期**: 2026-07-15  
> **状态**: 规划设计中

## 一、迭代背景与目标

### 1.1 V1 现状总结

| 维度 | V1 现状 | 问题/不足 |
|:---|:---|:---|
| 技术栈 | Vue 3 + Naive UI + Pinia + UnoCSS + Tauri 2 + Rust + SQLite | 与授权系统(React)技术栈不统一 |
| 认证 | localStorage 简单标记 `tea-logged-in=1` | 无真实用户认证、无 Token、无密码管理 |
| 权限 | 无角色权限系统 | 店员/店长无法区分权限 |
| 授权码 | 无 | 无法控制软件授权和机器绑定 |
| 数据安全 | SQLite 明文存储 | 无 SQLCipher 加密 |
| 代码架构 | 前端单文件大组件、后端 commands 大模块 | 可维护性差、耦合度高 |
| 业务功能 | 商品/库存/收银/会员/采购/退货/供应商/条码/打印/报表 | 功能基本完整但缺少深度业务场景 |
| 操作日志 | 无 | 无法追溯操作行为 |

### 1.2 V2 核心目标

1. **技术统一**: 采用与授权注册系统一致的 React + Ant Design 技术栈，便于深度集成
2. **安全加固**: 集成用户认证(Token+bcrypt)、角色权限、授权码管理、SQLCipher 数据库加密
3. **架构升级**: 前端模块化拆分、后端分层架构(Handler→Service→Repository)
4. **业务深化**: 完善库存防超卖、批次 FIFO、单位换算等核心算法
5. **体验提升**: 现代化 UI 设计、响应式交互、操作日志可追溯

### 1.3 V2 与 V1 的关键差异

| 维度 | V1 | V2 |
|:---|:---|:---|
| 前端框架 | Vue 3 + Naive UI | React 18 + Ant Design 5 |
| 状态管理 | Pinia | Zustand |
| 样式方案 | UnoCSS | Tailwind CSS |
| 认证方式 | localStorage 标记 | HMAC Token + bcrypt 密码 |
| 权限系统 | 无 | RBAC 角色权限 (店员/店长/管理员) |
| 授权管理 | 无 | 离线 HMAC 授权码 + 机器绑定 |
| 数据库 | SQLite 明文 | SQLite + SQLCipher 加密 (可选) |
| 后端架构 | 单层 commands | Handler→Service→Repository 分层 |
| 操作日志 | 无 | 全量操作日志记录 |

### 2.2 选型理由

| 技术 | 选型 | 理由 |
|:---|:---|:---|
| 前端框架 | React 18 | 与授权系统统一；生态成熟；组件复用 |
| UI 组件库 | Ant Design 5 | 企业级桌面端首选；表格/表单/布局完善 |
| 状态管理 | Zustand | 轻量、TypeScript 友好、无 Provider 嵌套 |
| 样式方案 | Tailwind CSS | 原子化、暗色模式支持好、与 Ant Design 兼容 |
| 路由 | React Router 6 | 主流方案、嵌套路由/懒加载 |
| 数据库 | SQLite + SQLCipher | 离线嵌入式、加密可选、rusqlite 成熟 |
| 密码哈希 | bcrypt | 工业标准、自适应成本因子 |
| 签名方案 | HMAC-SHA256 | 对称签名、性能好、足够安全 |
| 时间处理 | Day.js | 轻量、API 兼容 moment、国际化 |

## 四、核心模块设计

### 4.1 授权与认证模块（集成自 zhuceshouquan）

#### 4.1.1 授权码管理
- **离线 HMAC 签名**: 授权码 = `BASE64URL(payload_json).BASE64URL(hmac_signature)`
- **机器绑定**: SHA256(MAC + hostname) 前16位十六进制
- **有效期管理**: 支持永久授权和限期授权
- **本地持久化**: `license.json` 存储激活状态
- **启动校验**: 每次启动重新验证签名+机器+有效期

#### 4.1.2 用户认证
- **登录**: 用户名+密码（bcrypt 哈希，兼容旧 SHA-256）
- **Token**: HMAC-SHA256 签名，24h 过期，格式 `token_{userId}_{timestamp}_{signature}`
- **密码修改**: 验证旧密码 → bcrypt 新密码
- **记住密码**: 可选加密存储到本地

#### 4.1.3 角色权限 (RBAC)

用户(User) ←→ 角色(Role) ←→ 权限(Permission)

#### 4.2.2 多单位与价格定义（核心）

沿用 V1 设计，每个商品设定基准单位（称重类=g，计件类=pcs），可添加多个销售单位：

```
商品：牛栏坑肉桂（称重类，基准单位：克）
├── 克（基准）   1g    → 零售 0.8元  会员 0.75元

- 支持**批发价**（非会员的大客户价）
- 支持**促销价**（限时活动价）

### 4.3 库存管理模块（核心算法层）

#### 4.3.1 底层存储规则（沿用 V1）
- 称重类：`stock_grams`（整数，单位：克）
- 计件类：`stock_units`（整数，单位：个）

#### 4.3.2 入库换算逻辑
```
用户操作：采购入库"牛栏坑肉桂" 2件
↓
系统读取换算关系：1件 = 20罐，1罐 = 250g → 1件 = 5000g
↓
实际入库克数 = 2 × 5000 = 10000g
↓
BEGIN EXCLUSIVE TRANSACTION
  UPDATE products SET stock_grams = stock_grams + 10000 WHERE id = xxx
  INSERT INTO inventory_batches (...)
  INSERT INTO stock_flow (...)
COMMIT
```

#### 4.3.3 出库换算逻辑（FIFO 批次扣减）
```
用户操作：零售卖出"牛栏坑肉桂" 半斤（250g）
↓
BEGIN EXCLUSIVE TRANSACTION
  SELECT stock_grams FROM products WHERE id = xxx  -- 校验库存充足
  ↓
  FIFO 批次扣减：
  批次A（剩余3000g）→ 扣250g → 剩余2750g
  ↓ (如果批次A不够)
  批次B（剩余2000g）→ 扣剩余部分
  ↓
  UPDATE products SET stock_grams = stock_grams - 250
  UPDATE inventory_batches SET remaining_grams -= 扣减量
  INSERT INTO stock_flow (变更=-250g, 结余=新库存)
COMMIT
```

#### 4.3.4 防超卖保护（V2 增强）
- **数据库行级锁**: `BEGIN EXCLUSIVE TRANSACTION` 防止并发
- **库存校验**: 扣减前检查 `stock_grams >= 需求量`
- **配置开关**: 系统设置 `allowNegativeStock`（允许欠库存）
- **前端提示**: 库存不足弹窗"当前库存仅剩 X g，是否继续？"

#### 4.3.5 库存显示逻辑
```
库存 7750g ÷ 5000g/件 = 1件 + 2750g
2750g ÷ 250g/罐 = 11罐
显示："1件 11罐 (7750g)"
```

    id TEXT PRIMARY KEY NOT NULL,
    username TEXT NOT NULL UNIQUE,
    password_hash TEXT NOT NULL,
    real_name TEXT,
    phone TEXT,
    email TEXT,
    avatar TEXT DEFAULT '',
    status INTEGER NOT NULL DEFAULT 1,
    last_login_at TEXT,
    created_at TEXT NOT NULL DEFAULT (datetime('now')),
    updated_at TEXT NOT NULL DEFAULT (datetime('now'))
);
```

#### roles（角色表）
```sql
CREATE TABLE roles (
    id TEXT PRIMARY KEY NOT NULL,
    name TEXT NOT NULL UNIQUE,
    description TEXT,
    is_system INTEGER NOT NULL DEFAULT 0,
    created_at TEXT NOT NULL DEFAULT (datetime('now')),
    updated_at TEXT NOT NULL DEFAULT (datetime('now'))
);
```

#### user_roles（用户-角色关联）
```sql
CREATE TABLE user_roles (
    user_id TEXT NOT NULL,
    role_id TEXT NOT NULL,
    PRIMARY KEY (user_id, role_id),
    FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE,
    FOREIGN KEY (role_id) REFERENCES roles(id) ON DELETE CASCADE
);
```

CREATE TABLE role_permissions (
    role_id TEXT NOT NULL,

);

);

## 九、安全设计

### 9.1 认证安全
- 密码使用 bcrypt 哈希（成本因子 12）
- Token 使用 HMAC-SHA256 签名，24h 过期
- 登录失败次数限制（5次锁定30分钟）
- 支持"记住密码"（AES 加密存储）

### 9.2 授权安全
- 离线 HMAC-SHA256 授权码签名
- 机器指纹绑定（MAC + hostname）
- 有效期检查（永久/限期）
- 本地不存储明文授权码

### 9.3 数据安全
- SQLite 可选 SQLCipher 加密
- 数据库文件权限控制
- 定期备份提醒
- 敏感操作二次确认

### 9.4 前端安全
- CSP 内容安全策略
- XSS 防护（HTML 转义）
- 路由守卫（未登录重定向）
- 权限守卫（无权限拒绝渲染）
