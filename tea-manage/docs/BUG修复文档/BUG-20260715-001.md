# BUG 修复报告 — v0.7.1 回归

- **报告日期**：2026-07-15
- **版本**：v0.7.0 → v0.7.1（无数据库变更，patch）
- **触发**：用户反馈「全面的回归测试，发现很多问题，例如打开显示白屏没有任何内容」
- **结论**：白屏为生产构建路径问题；其余「很多问题」根因为 **Naive UI 组件在 `main.ts` 全局注册时缺漏**（全站彩色文字/列表/栅格丢失 Naive UI 样式）。两者均已修复，并建立 Playwright E2E 回归基线（29 用例全绿）+ 清理由过时 jsdom 视图测试导致的 `npm run test` 误报。

---

## BUG-1：生产构建打开白屏（无任何内容）

| 项 | 内容 |
|----|------|
| 严重度 | P0（应用完全不可用） |
| 现象 | 打包后打开应用，整页白屏，无任何文字/控件，控制台亦无明显报错 |
| 根因 | Vite 默认 `base: '/'`，生产 webview 从 `tauri://localhost` 加载。Tauri 在 Windows 构建时会将绝对路径 `/assets/xxx.js` 改写为 `http://tauri.localhost/assets/xxx.js`（Tauri issue #13262），该来源被 webview 的 CSP 拦截，导致入口脚本不加载 → 白屏 |
| 修复 | `vite.config.ts` 设 `base: './'`（相对路径，由 webview 自身源解析）；`src/router/index.ts` 改用 `createWebHashHistory()`（hash 路由规避 history 模式下的路径重写）；`src/utils/errorGuard.ts` 全局错误守卫，运行时异常以可见面板呈现而非静默白屏 |
| 验证 | 构建产物 `dist/index.html` 引用 `./assets/index-*.js`（相对路径）；`npm run build` 通过 |
| 残留影响 | hash 路由下所有导航/URL 断言需带 `#`（如 `/#/products`），E2E 已适配 |
| 风险 | 低。相对路径是 Tauri 官方推荐做法 |

## BUG-2：Naive UI 组件未注册 — 全站样式丢失（pre-existing 回归）

| 项 | 内容 |
|----|------|
| 严重度 | P1（视觉/交互大面积异常，用户感知为「很多问题」） |
| 现象 | 应用可打开，但：① 所有 `n-text type="primary/error/success"` 彩色文字失去主题色；② 单位选择弹窗、挂单列表的列表项无 Naive UI 样式；③ 首页/打印模板的 `n-grid`/`n-gi` 栅格错乱 |
| 根因 | `src/main.ts` 用 `create({ components: [...] })` 显式全局注册 Naive UI 组件，但列表**缺漏 8 个**：`NText / NList / NListItem / NGrid / NGi / NButtonGroup / NPagination / NRadioButton`。Vue 对未注册的组件按原生 custom element 渲染（如 `<n-text>`、`<n-list-item>`），丢失 Naive UI 的 class 与主题 CSS 变量。`git log -S "NText"` 证实这些组件**从未被注册**（早期即存在，非本次引入） |
| 修复 | `src/main.ts` 在 import 段与 `components` 数组同步补登上述 8 个组件 |
| 验证 | 注入调试：修复前 `n-text` 渲染为 `<n-text>50g</n-text>`（裸标签）；修复后渲染为 `<span class="n-text" style="--n-text-color:#4A6741">50g</span>`（深茶绿主题生效）。`n-list-item` 由 `<n-list-item class="cursor-pointer">` 变为 `<li class="n-list-item">` |
| 影响面 | `n-text` 涉及 **15 个文件**（全站金额/状态语义着色），修复后恢复；其余组件涉及收银弹窗、首页栅格、单选按钮组、分页等 |
| 风险 | 低。仅追加组件注册，不改变任何业务逻辑 |

> 排查手段：在浏览器中 dump 模态 DOM，发现 `n-list-item` 计数=0 但 `htmlTail` 含 `<n-list-item ...>50g...100g...</n-list-item>`，判定其为**标签名而非 CSS 类**，进而定位到组件未注册。

## BUG-3：E2E 回归用例 3 个失败（测试逻辑问题，非应用 bug）

| 用例 | 失败现象 | 根因 | 修复 |
|------|---------|------|------|
| 点击商品应添加到购物车 | 购物车仍显示「点击左侧商品添加到购物车」 | 测试未处理多单位商品弹出的单位选择弹窗 | 补充：定位 `选择购买单位` 弹窗并点击首个 `.n-list-item` |
| 完整结算流程 | 结算按钮 `disabled`，点击超时 | 弹窗定位器 `hasText:'选择单位'` 不是标题 `选择购买单位` 的连续子串 → 弹窗未被定位 → 单位未选 → 购物车空 → 结算禁用 | 定位器改为 `选择购买单位` |
| 清空购物车按钮 | 同上，空购物车文本仍可见 | 同上 | 同上 |

**前置修复（前序）**：E2E `injectMockTauri` 未设 `localStorage['tea-logged-in']='1'`，路由守卫将所有非公开路由重定向到 `/login`，用例永远停留在登录页。已在 mock 注入时补齐该标志。

**结果**：`npx playwright test` → **29 passed (29)**，0 failed。

## BUG-4：测试配置误收集（npm run test 误报失败）

| 项 | 内容 |
|----|------|
| 现象 | `npm run test` 报 3 个 Failed Suites（`tests/e2e/*.spec.ts`），但 559 个测试全过 |
| 根因 | `vitest.config.ts` 的 `include: ['tests/**/*.spec.ts']` 匹配到 Playwright E2E 用例，Vitest 尝试执行 `@playwright/test` 的 `test.describe()` 报 `Playwright Test did not expect test.describe()` |
| 修复 | `vitest.config.ts` 的 `exclude` 增加 `tests/e2e/**` |
| 附带 | 删除 3 个过时的 jsdom 视图测试（`ProductList/InventoryPage/SalesPage.test.ts`，断言 v0.6.0 前不存在的 DOM，已被真实浏览器 E2E 取代） |
| 结果 | `npm run test` → **18 files, 559 tests passed**，exit 0 |
