# UI 整体优化方案（合理项，非过度优化）

> 配套《代码审查报告-2026-07-15.md》
> 原则：**只做能提升日常经营效率 / 降低误操作 / 补全业务信息化的改动**，不为美观而改。
> 优先级：P0 必做（低成本高收益）→ P1 建议 → P2 可选。

---

## P0 — 必做（低成本、高收益）

### 1. 收银台：会员折扣关闭时显式提示
- **痛点**：关闭「启用会员折扣」后，折扣行直接消失，收银员无法判断是「无会员」还是「开关关了」，易误以为 bug。
- **优化**：`discountAmount === 0` 且无会员 → 不显示；有会员但开关关闭 → 显示灰色提示「会员折扣已关闭」。
- **收益**：消除歧义，降低培训成本。
- **风险**：极低（纯展示逻辑）。

### 2. 报表 / 销售历史：导出 CSV
- **痛点**：销售报表、销售历史无导出，对账 / 报税需手动抄录。
- **优化**：列表页增加「导出 CSV」按钮，前端按当前筛选条件生成 Blob 下载。
- **收益**：直接补全「业务信息化覆盖」诉求。
- **风险**：低（纯前端，注意中文 CSV 加 BOM 防乱码）。

### 3. 库存页：低库存快捷筛选 + 预警徽标
- **痛点**：低库存预警色已有，但需逐行肉眼找。
- **优化**：库存列表顶部增加「仅看预警」开关；导航/卡片显示预警商品数量徽标。
- **收益**：补货决策效率提升。
- **风险**：低（复用现有低库存判定阈值）。

### 4. 长操作统一 loading 反馈
- **痛点**：初始化数据库 / 生成演示数据 / 备份期间按钮无禁用态，用户易重复点击。
- **优化**：`initDatabase`、`seedDemoData` 调用期间按钮 `:loading`，结束才解锁。
- **收益**：防重复操作、体验一致。
- **风险**：极低（已在 I3 接入，补 loading 即可）。

---

## P1 — 建议（中等成本，明确收益）

### 5. 表单实时校验
- **痛点**：手机号、数量、单价仅提交时校验，报错后才改。
- **优化**：`n-form` 加 `:rules`，输入即校验，错误态高亮。
- **收益**：减少提交失败往返。
- **风险**：低。

### 6. 收银台快捷键
- **痛点**：高频操作（结算 / 挂单 / 会员识别）靠鼠标点。
- **优化**：F2 结算、F3 挂单、Enter 加购。
- **收益**：熟手效率提升明显。
- **风险**：中（需避免与输入框冲突，且仅在收银台路由生效）。

### 7. 列表大数据量虚拟滚动
- **痛点**：商品 / 会员 / 销售历史行数多时整页渲染卡顿。
- **优化**：千行以上改用 `n-data-table` 虚拟滚动或分页默认。
- **收益**：性能稳健。
- **风险**：中（需回归各列表渲染）。

## P2 — 可选（按需，谨慎评估）

### 8. 首页仪表盘经营洞察
- 增加「今日目标完成率 / 环比昨日」卡片（需轻量聚合，可前端基于已加载数据统计）。
- 收益：经营决策；风险：中（数据口径需与报表一致）。

### 9. 窄屏 / 响应式适配
- POS 收银台在笔记本窄屏下商品网格列数自适应、侧栏可折叠。
- 收益：多设备；风险：中（布局回归测试）。

### 10. 深色模式（系统主题跟随）
- **不建议本轮做**。深茶绿为品牌色，深色模式需重新校验全部对比度，易引入可读性问题。标注为「未来可选」，非必须。

### 11. 小票模板编辑
- 当前模板写死 `default`，增加模板管理（已在路线图，非紧急）。

---

## 明确不做（避免过度优化）

- ❌ 引入第三方 UI 动画库 / 重改视觉风格（已有统一深茶绿规范，改了反而破坏一致性）。
- ❌ 把 mdi 图标换成其他图标集（全站已统一 mdi）。
- ❌ 增加非业务相关的装饰性页面 / 仪表盘花哨图表。
- ❌ 把单机应用硬改成多租户 / 云端架构（超出本期范围，且违背单机茶店定位）。

---

## 推荐实施顺序

1. 本轮可顺手完成：P0-1（折扣提示）、P0-4（loading）。
2. 下一小迭代：P0-2（CSV 导出）、P0-3（低库存筛选）。
3. 待确认需求后再做：P1 / P2。

> 所有 P1/P2 涉及新功能或较大改动，按流程需先与用户确认范围后再实现。
