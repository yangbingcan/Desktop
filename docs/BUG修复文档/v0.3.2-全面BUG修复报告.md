# v0.3.2 全面 BUG 修复与系统稳定化报告

> **版本号**：v0.3.2
> **修复日期**：2026-07-03
> **版本类型**：patch（系统稳定化 + 序列化修复）

## 一、问题背景

用户在实际使用中报告了 5 类核心 BUG，并指出"应用的边界以及系统的稳定开展业务"问题。开发组对项目进行了全面排查，发现根本问题集中在三个层面：

1. **后端 Rust 结构体缺失 `#[serde(rename_all = "camelCase")]`**，导致商品相关接口序列化字段与前端期望不一致
2. **Tauri 2.x 命令参数命名约定理解不一致**，部分前端调用用 camelCase 而后端是 snake_case
3. **菜单架构冗余**，列表与新增被拆为两个独立菜单入口

---

## 二、根因分析

### 2.1 根因 1：后端结构体序列化字段名不一致

Tauri 2.x 的 IPC 通信规则：
- **返回值（结构体序列化）**：遵循结构体自身的 `#[serde(rename_all)]` 注解
- **命令参数（函数参数）**：Tauri 命令默认 `rename_all = "snake_case"`

项目内 **10 个结构体** 已有正确的 `#[serde(rename_all = "camelCase")]`：
- `InventoryItem`、`InventoryDetail`、`InventoryBatch`、`StockFlow`（inventory.rs）
- `Member`、`MemberInput`、`MemberUpdate`、`MemberDetail`、`SaleOrder`、`HeldOrder`（sales.rs）
- `CategoryTree`、`CategoryInput`、`CategoryUpdate`（category.rs）
- `Supplier`、`SupplierInput`（supplier.rs）
- `MemberBalance` 相关（member_balance.rs）
- `ReturnOrder` 系列（return_order.rs）
- `ProductInput`、`SalesUnitInput`（product.rs）

但 **5 个结构体缺失**该注解，导致返回字段为 snake_case，前端 camelCase 访问全部失败：

| 缺失结构体 | 后端字段（snake_case） | 前端字段（camelCase） | 失败表现 |
|------------|----------------------|---------------------|---------|
| `Product` | `category_id`、`base_unit`、`is_active`、`default_unit_id`、`image_url` | `categoryId`、`baseUnit`、`isActive` 等 | 商品列表分类显示为空、编辑/新增类型错误 |
| `ProductUpdate` | `category_id`、`fermentation_level`、`roast_level`、`image_url` | `categoryId`、`fermentationLevel`、`roastLevel` | 更新时这些字段被 serde 忽略，"修改保存后无效果" |
| `SalesUnit` | `product_id`、`conversion_to_base`、`retail_price`、`member_price` | `productId`、`conversionToBase`、`retailPrice`、`memberPrice` | 销售单位列表全是 `undefined`，"添加商品失败" |
| `PageResult<T>` | `page_size` | `pageSize` | 分页参数错位 |
| `Category` | `parent_id`、`sort_order` | `parentId`、`sortOrder` | 分类管理显示异常 |

### 2.2 根因 2：Tauri 命令参数命名错误

Tauri 2.x `#[tauri::command]` 默认 `rename_all = "snake_case"`，函数参数名与前端调用 key 必须完全匹配（snake_case）。

**问题调用**（[purchases.ts:40](file:///d:/AI/AI/开发/茶叶店管理/tea-manage/src/api/purchases.ts#L40)）：
```ts
export async function getPurchaseOrderDetail(orderId: string): Promise<PurchaseOrder> {
    return await invoke('get_purchase_order_detail', { orderId })  // ❌ camelCase
}
```
后端命令：
```rust
#[tauri::command]
pub async fn get_purchase_order_detail(
    db: tauri::State<'_, Database>,
    order_id: String,  // ← snake_case
) -> Result<PurchaseOrder, String>
```

### 2.3 根因 3：菜单结构冗余

现有结构中"商品档案"、"采购入库"、"会员管理"等菜单都有父子结构，子项包含"列表"和"新增"两个独立入口。

**问题**：
- 用户认知负担：进入"商品档案" → 看到"列表"和"新增"两个并列项 → 疑惑该用哪个
- 工作流断裂：用户要新增商品时需要先点"商品档案"→"新增商品"两步操作
- 与项目规则冲突：所有列表+操作应在同一个页面（弹窗/抽屉/Drawer）

**正确做法**：
- 移除所有"新增"独立菜单项
- 列表页头部保留"新增"按钮（点击后弹出 Drawer/Modal 表单）
- 父菜单点击时直接导航到对应的列表页

### 7.2 根因分析

#### 7.2.1 Tauri 2.x 命令参数命名约定

Tauri 2.x 的 `#[tauri::command]` 宏默认使用 `rename_all = "snake_case"` 处理函数参数名。前端 `invoke()` 调用时，对象的 key 必须与函数参数名完全一致（snake_case）。

#### 7.2.2 复现路径

- **BUG-6/7/8**（退货模块）：点击退货单"查看"或"删除"按钮 → 后端返回 `missing required key 'order_id' / 'product_id'` → 用户看到"加载失败"或"删除失败"
- **BUG-9**（会员储值流水）：打开会员详情 → 点击"储值流水"Tab → 后端返回 `missing required key 'member_id'` → 流水列表为空
- **BUG-10**（最近支付方式）：在退款弹窗初始化时调用 → 退款方式下拉默认值无法回填
- **BUG-11**（API 模块导出）：其他模块需从 `@/api` 统一入口导入时找不到 `getPurchaseOrders`、`getReturnOrders` 等函数

#### 7.2.3 错误示例

```ts
// ❌ 错误 - 触发 Tauri 参数缺失错误
export async function getReturnOrderDetail(orderId: string): Promise<ReturnOrder> {
    return await invoke('get_return_order_detail', { orderId })
}

// ✅ 正确 - 与后端 snake_case 参数名匹配
export async function getReturnOrderDetail(orderId: string): Promise<ReturnOrder> {
    return await invoke('get_return_order_detail', { order_id: orderId })
}
```

## 九、v0.3.2 增量修复（第 3 轮：销售台"添加商品失败"深度排查）

> **修复日期**：2026-07-03
> **触发原因**：用户报告销售台点击添加商品仍提示"添加商品失败"，需深度定位根因

### 9.1 深度排查结论

通过 Playwright 启动 vite dev 模拟前端环境（暴露 invoke 实际行为）发现：

| 排查项 | 结论 |
|--------|------|
| 浏览器中 invoke 行为 | `TypeError: Cannot read properties of undefined (reading 'invoke')` |
| 根本原因定位 | **Tauri 2.x invoke 在非 Tauri runtime 中完全不可用**，所有 catch 块必须暴露真实错误 |
| 销售台 catch 块 | 之前是写死的"添加商品失败"字符串，**用户看不到真实错误，无法定位问题** |
| onMounted 错误处理 | 之前完全没有 try-catch，**初始化错误被静默吞掉** |
