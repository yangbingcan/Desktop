## 二、问题描述

### 2.1 问题现象

用户反馈两类核心 UI 问题：

**问题 1 - 主题适配（首页与多页面）**：
- 首页和其他页面在深色主题下存在白色背景

## 三、问题分析

### 3.1 根因分析

#### 根因 1 - 首页图标不可见

`QuickActions.vue` 和 `TodayStats.vue` 中图标 `color` 与 `bgColor` 使用同色相的 `--tea-accent-*` 系列：

```js
// 原 QuickActions.vue
{ key: 'sales', color: 'var(--tea-accent-primary)', bgColor: 'var(--tea-primary-supply)' }
{ key: 'products', color: 'var(--tea-accent-success)', bgColor: 'var(--tea-accent-success-bg)' }
```

- `--tea-accent-success` = `#5B8C5A`（茶绿）
- `--tea-accent-success-bg` = `rgba(91,140,90,0.12)`（同色相浅底）

**对比度仅 3.2:1**，不达 WCAG AA 标准（≥ 4.5:1），导致图标与底色"融为一体"。

#### 根因 2 - 商品档案深色模式固定列穿透

`n-overrides.css` 中两处规则将深色模式下的 `n-data-table-td` 背景设为 `transparent`：

```css
/* 第 720-727 行（v0.5.2 之前） */
[data-theme='dark'] .n-data-table .n-data-table-td,
[data-theme='dark'] .n-data-table .n-data-table-tr .n-data-table-td {
  background: transparent !important;  /* ← 问题所在 */
}

/* 第 921-927 行（v0.5.2 兜底） */
[data-theme='dark'] .n-data-table .n-data-table-td,
[data-theme='dark'] .n-data-table-td,
[data-theme='dark'] .n-data-table .n-data-table-th,
[data-theme='dark'] .n-data-table-th {
  background: transparent !important;  /* ← 问题所在 */
}
```

**机制**：Naive UI 的 `n-data-table` 固定列实现依赖 `position: sticky`，sticky 元素需要不透明背景才能遮挡下层滚动内容。浅色模式下 td 默认有白色背景所以不穿透；深色模式下被强制 transparent，导致穿透。

#### 根因 3 - 删除按钮无底色

`ProductList.vue` 第 468 行使用 `ghost: true`：

```js
h(NButton, { size: 'small', type: 'error', ghost: true }, { default: () => '删除' })
```

`ghost: true` 是 Naive UI 的"幽灵样式"——空心透明背景、仅边框，导致按钮没有底色。

## 四、修复方案

### 4.1 修复思路

#### 方案 1 - 新增图标专用色变量（修复首页图标）

新增 `--tea-icon-*` 系列变量，比 `--tea-accent-*` 更深（浅色）/更亮（深色），与同色相浅底背景对比度 ≥ 5:1（WCAG AA）。

**色值设计**：
| 变量 | 浅色模式 | 与同色相浅底对比度 | 深色模式 | 与暗色背景对比度 |
|------|---------|-------------------|---------|----------------|
| `--tea-icon-primary` | `#8A5A30` | 5.6:1 | `#E0A55C` | 9.2:1 |
| `--tea-icon-success` | `#2D5C2C` | 6.1:1 | `#A8D2A6` | 10.5:1 |
| `--tea-icon-info` | `#1A4D80` | 7.2:1 | `#9CC5E8` | 8.8:1 |
| `--tea-icon-warning` | `#8A4A0F` | 5.8:1 | `#F0C896` | 11.2:1 |
| `--tea-icon-danger` | `#8A2A30` | 5.9:1 | `#F0AAB0` | 9.5:1 |
| `--tea-icon-purple` | `#5B3FAE` | 5.4:1 | `#C4A0FF` | 8.6:1 |
| `--tea-icon-emerald` | `#0F7A55` | 5.7:1 | `#6EE7B7` | 12.1:1 |
| `--tea-icon-gray` | `#4A5260` | 6.3:1 | `#B0B7C3` | 9.8:1 |

#### 方案 2 - 表格 td 实色背景（修复商品档案穿透）

将深色模式下 `n-data-table-td` 的 `background: transparent` 改为 `background: var(--tea-surface-2)`（卡片背景色，不透明）。

- 普通表格：td 背景 = 卡片背景 = `surface-2`，与卡片融为一体
- 固定列：td 背景 = `surface-2`，不透明，遮挡下层
- 斑马纹行：已有规则用 `surface-3`，特异性更高，正常覆盖
- hover 行：改为 `--tea-surface-hover`（带主色调），与卡片视觉一致

#### 方案 3 - 删除按钮去掉 ghost（修复无底色）

去掉 `ghost: true`，让按钮变为 Naive UI 默认的实心样式，红色背景 + 白色文字。

### 7.2 第三轮根因

#### 问题 1 + 2：弹窗/抽屉不显示

**根因**：n-overrides.css 第 2065-2084 行三条"防御性" CSS 规则基于错误的类名假设。

```css
.n-drawer:not(.n-drawer--show),
.n-modal:not(.n-modal--show) {
  pointer-events: none !important;
  display: none !important;
}

.n-drawer-container:not(.n-drawer-container--show),
.n-modal-container:not(.n-modal-container--show) {
  opacity: 0 !important;
  visibility: hidden !important;
}

.n-drawer-mask:not(.n-drawer-mask--show),
.n-modal-mask:not(.n-modal-mask--show) {
  opacity: 0 !important;
  visibility: hidden !important;
  display: none !important;
}
```

**Playwright 实测验证**（点击"一键清空数据"按钮后 1 秒内连续 20 次采样）：

| 时间 (ms) | container className | container visibility | mask display | card display |
|----------|---------------------|---------------------|--------------|--------------|
| 0~950 | `n-modal-container`（始终无 `--show` 后缀） | hidden | none | none |

**结论**：Naive UI 在显示过程中**不会**通过添加 `--show` 后缀类来标记状态。这三条规则导致 modal/drawer 一旦进入"显示过渡"就被 `display: none` 强制打断，永远不可见。

#### 问题 3：演示数据生成 UNIQUE 约束失败

**根因**：`src-tauri/src/commands/dev_data.rs` 中 `seed_demo_data` 命令对 `products` 表使用 `INSERT INTO`（非 `OR IGNORE`/`OR REPLACE`），而 `products.code` 字段有 UNIQUE 约束。数据库已有数据时，再次点击触发 `UNIQUE constraint failed: products.code`。

### 7.3 第三轮修复方案

#### 修复 1：移除错误的 CSS 规则

删除 n-overrides.css 中三条基于错误类名假设的规则，让 Naive UI 内部 transition 机制正常工作。

#### 修复 2：seed_demo_data 幂等化

重构 dev_data.rs：
1. 提取 `clear_business_tables(conn, rollback)` 内部函数，封装清空业务表逻辑
2. `seed_demo_data` 在事务开始后、插入数据前先调用 `clear_business_tables`，保证幂等
3. `clear_all_data` 改为调用同一内部函数（行为不变）
