| 项目 | 内容 |

## 二、技术栈决策

### 2.1 前端技术栈

| 技术 | 选择 | 理由 |
|------|------|------|
| 框架 | React 18 | 生态成熟，组件丰富，团队熟悉 |
| 语言 | TypeScript | 类型安全，提升开发效率和代码质量 |
| 状态管理 | Zustand | 轻量、简洁、TypeScript友好 |
| UI 组件库 | Ant Design 5 | 企业级组件库，表格/表单组件完善，适合管理系统 |
| 样式方案 | TailwindCSS 3 | 原子化CSS，快速布局，与Ant Design互补 |
| 构建工具 | Vite 5 | 极速HMR，Tauri官方推荐 |

### 2.2 后端技术栈

| 技术 | 选择 | 理由 |
|------|------|------|
| 语言 | Rust | 高性能、内存安全，Tauri原生语言 |
| 框架 | Tauri 2 Command + Axum | Tauri IPC处理本地调用，Axum处理服务端RPC |
| 数据库 | SQLite (rusqlite) | 零配置、本地文件、单机场景最优 |
| ORM | 无（手写SQL） | SQLite场景简单，手写SQL更灵活高效 |

### 2.3 桌面端框架

| 技术 | 选择 | 理由 |
|------|------|------|
| 框架 | Tauri 2 | 比Electron更小体积、更低内存、更安全 |
| 窗口管理 | 自定义标题栏（decorations: false） | 统一视觉风格，支持深色/浅色主题 |
| 安装包 | NSIS | Windows标准安装方案，支持自定义安装路径 |

### 2.4 服务端（可选）

| 技术 | 选择 | 理由 |
|------|------|------|
| 框架 | Axum | Rust生态最成熟的Web框架 |
| 通信 | HTTP RPC + SSE | RESTful API + 服务器推送事件 |
| 端口 | 9520 | 固定端口，局域网访问 |
| 代码复用 | path依赖src-tauri | 零代码重复，34个业务模块完全共享 |

## 三、方案对比

### 3.1 桌面端框架对比

| 方案 | 优点 | 缺点 | 推荐度 |
|------|------|------|--------|
| Tauri 2 | 体积小(10MB)、内存低、安全、Rust后端 | 生态不如Electron成熟 | ★★★★★ |
| Electron | 生态成熟、文档丰富 | 体积大(100MB+)、内存高 | ★★★☆☆ |
| Qt | 原生性能 | 学习曲线陡、开发效率低 | ★★☆☆☆ |

### 3.2 前端框架对比

| 方案 | 优点 | 缺点 | 推荐度 |
|------|------|------|--------|
| React | 生态最大、组件库多、灵活 | 需要额外状态管理 | ★★★★★ |
| Vue | 上手简单、中文社区活跃 | 大型项目不如React灵活 | ★★★★☆ |

### 3.3 数据库对比

| 方案 | 优点 | 缺点 | 推荐度 |
|------|------|------|--------|
| SQLite | 零配置、单文件、高性能 | 不支持高并发写入 | ★★★★★ |
| PostgreSQL | 功能强大、支持并发 | 需要安装配置 | ★★★☆☆ |

## 四、最终推荐

### 推荐方案
- 桌面端：Tauri 2 + React 18 + TypeScript + Vite
- 前端UI：Ant Design 5 + TailwindCSS
- 状态管理：Zustand
- 后端：Rust + Tauri Command + SQLite
- 服务端（可选）：Axum + HTTP RPC

### 推荐理由
1. **Tauri 2**：安装包仅10MB，内存占用低，Rust后端性能卓越
2. **React + Ant Design**：企业级管理系统最佳组合，表格/表单/弹窗组件完善
3. **SQLite**：零配置本地数据库，单机场景最优解，无需安装数据库服务
4. **Rust + Axum**：服务端与桌面端共享核心业务库，零代码重复

## 五、风险评估

| 风险 | 影响 | 应对措施 |
|------|------|---------|
| Tauri 2生态不够成熟 | 部分功能需要自己实现 | 核心功能已验证可行，社区活跃 |
| Rust学习曲线 | 开发速度可能较慢 | 后端逻辑相对简单，已有成熟模式 |
| SQLite并发限制 | 局域网多用户写入冲突 | 服务端通过Axum串行化写入 |
| Ant Design包体积 | 前端包较大 | 按需引入，Vite tree-shaking |
