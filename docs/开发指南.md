### 步骤 6：数据库迁移（给 admin 角色添加默认权限）

在 [src-tauri/src/database.rs](file:///d:/AI/AI/JXC/GLTauriRust/src-tauri/src/database.rs) 中新增一个迁移函数，或在现有的最新迁移中添加：

```rust
fn migrate_v11(conn: &Connection) -> Result<(), String> {
    // 给 admin 角色添加新模块权限
    let perm_id = uuid::Uuid::new_v4().to_string();
    conn.execute(
        "INSERT OR IGNORE INTO role_permissions (id, role_name, permission_key) VALUES (?1, 'admin', 'product')",
        rusqlite::params![perm_id],
    ).map_err(|e| format!("v11迁移失败(权限): {}", e))?;

    conn.pragma_update(None, "user_version", 11).map_err(|e| e.to_string())?;
    Ok(())
}
```

并在 `migrate()` 函数中调用：

```rust
if version < 11 {
    migrate_v11(conn)?;
}
```

> **注意**：`INSERT OR IGNORE` 确保多次执行不会重复插入。`role_name = 'admin'` 是系统内置管理员角色，其 `is_system = 1`。

## 三、后端开发指南

### 3.1 Rust 模块开发模式

每个业务模块遵循统一的三层模式：

```
═══════════════════════════════════════════
  业务逻辑函数 (_logic)     ← 纯函数，不依赖 Tauri State
═══════════════════════════════════════════
  Tauri Command (#[tauri::command])  ← 薄包装，从 State 获取 conn
═══════════════════════════════════════════
  服务端内部函数 (_inner)   ← server 模式用，解析 JSON 参数
═══════════════════════════════════════════
```

**示例（以用户管理为例）**：

```rust
// 1. 业务逻辑（Tauri 和 server 模式共用）
fn get_users_logic(conn: &Connection, secret: &[u8], token: &str, params: GetUsersParams) -> Result<GetUsersResult, String> {
    let ctx = verify_and_get_context(conn, token, secret)?;
    ctx.require_permission("user_manage")?;  // 权限检查
    // ... 业务逻辑
}

// 2. Tauri Command（薄包装）
#[tauri::command]
pub fn get_users(db: State<'_, DbState>, token_secret: State<'_, TokenSecret>, token: String, params: GetUsersParams) -> Result<GetUsersResult, String> {
    let conn = crate::database::get_conn_ref(&db)?;
    get_users_logic(&conn, &token_secret, &token, params)
}

// 3. 服务端内部函数（server 模式）
#[cfg(feature = "server")]
pub fn get_users_inner(conn: &Connection, secret: &[u8], args: &Value) -> Result<Value, String> {
    let params: GetUsersParams = serde_json::from_value(args.clone())?;
    let result = get_users_logic(conn, secret, &arg_str(args, "token"), params)?;
    serde_json::to_value(result).map_err(|e| format!("序列化失败: {}", e))
}
```

### 3.2 注册 Tauri Command

在 [src-tauri/src/lib.rs](file:///d:/AI/AI/JXC/GLTauriRust/src-tauri/src/lib.rs) 的 `invoke_handler` 中注册：

```rust
.invoke_handler(tauri::generate_handler![
    // ... 已有命令
    your_module::your_command,   // 新增
])
```

### 3.3 注册 HTTP RPC 路由（server 模式）

在 [src-tauri/src/server.rs](file:///d:/AI/AI/JXC/GLTauriRust/src-tauri/src/server.rs) 的 `dispatch_command` 中添加：

```rust
"your_command" => run_command(|| crate::your_module::your_command_inner(conn, secret, &req.args)),
```

### 3.4 鉴权上下文使用

所有业务逻辑函数必须通过 `verify_and_get_context` 获取鉴权上下文，并进行权限检查：

```rust
let ctx = verify_and_get_context(conn, token, secret)?;
ctx.require_permission("模块key")?;           // 模块级权限
ctx.require_permission("模块key:delete")?;    // 操作级权限（如删除）
```

- `require_permission("product")` — 检查是否有 product 模块或其任意操作权限
- `require_permission("product:delete")` — 检查是否有 product 模块的 delete 操作权限
- 超级管理员（`is_super_admin = true`）自动通过所有权限检查

### 3.5 数据库操作模式

项目使用手写 SQL（不引入 ORM），标准模式：

```rust
// 查询
let mut stmt = conn.prepare("SELECT ...")?;
let items = stmt.query_map(params![...], |row| row_to_xxx(row))?;

// 写入（使用事务保证原子性）
let tx = conn.unchecked_transaction()?;
tx.execute("INSERT INTO ...", params![...])?;
tx.execute("UPDATE ...", params![...])?;
tx.commit()?;
```

### 3.6 操作日志记录

在关键操作后调用：

```rust
crate::operation_logs::record_operation_log(
    conn, &ctx.username, "create", "创建商品", "商品管理", Some(&format!("商品: {}", name))
);
```

`record_operation_log` 会自动采集计算机名、IP、MAC、操作系统版本、应用版本等信息。

## 五、权限系统详解

### 5.1 数据库表关系

```
users ──┐                    roles ──┐
         │ user_roles                 │ role_permissions
         │ (user_id, role_id)         │ (role_id, permission_key)
         └────────────────────────────┘
```

| 表 | 用途 |
|----|------|
| `users` | 用户基本信息 |
| `roles` | 角色定义（`is_system=1` 为系统角色，不可删除/修改名称） |
| `user_roles` | 用户-角色关联（多对多） |
| `role_permissions` | 角色-权限关联（`permission_key` 如 `product:view`） |

### 5.2 权限粒度

权限 key 格式为 `模块:操作`，共两级：

- **模块级**：仅分配模块 key（如 `product`），用户拥有该模块所有操作权限
- **操作级**：分配完整 key（如 `product:view`、`product:add`），细粒度控制

### 5.3 超级管理员

`is_super_admin` 通过以下 SQL 判断：

```sql
SELECT EXISTS(
  SELECT 1 FROM user_roles ur
  JOIN roles r ON ur.role_id = r.id
  WHERE ur.user_id = ? AND r.is_system = 1
)
```

- 拥有 `is_system = 1` 角色的用户自动成为超级管理员
- 超级管理员跳过所有权限检查
- 系统内置 `admin` 角色的 `is_system = 1`

### 5.4 权限流转路径

```
用户登录 → load_user_permissions(user_id)
         → SELECT DISTINCT rp.permission_key
           FROM user_roles ur
           JOIN role_permissions rp ON ur.role_id = rp.role_id
           WHERE ur.user_id = ?
         → 返回权限列表（如 ["dashboard", "product:view", "product:add"]）

路由访问 → hasPermissionForRoute(pathname, permissions, isSuperAdmin)
         → 匹配 routePermissionMap 中的路由前缀
         → 检查权限列表中是否包含对应模块或模块:操作
```

### 5.5 15 种操作类型

| key | 显示名 | key | 显示名 |
|-----|--------|-----|--------|
| `view` | 查看 | `edit_date` | 修改业务日期 |
| `add` | 新增 | `edit_other` | 修改其他信息 |
| `edit` | 修改 | `preview` | 预览 |
| `delete` | 删除 | `print` | 打印 |
| `audit` | 审核 | `design_report` | 设计报表 |
| `unaudit` | 消审 | `import` | 导入 |
| `void` | 冲单 | `export` | 导出 |
| | | `terminate` | 终止 |

## 六、数据库迁移机制

### 6.1 版本化迁移

数据库版本通过 SQLite 的 `PRAGMA user_version` 管理，在 [src-tauri/src/database.rs](file:///d:/AI/AI/JXC/GLTauriRust/src-tauri/src/database.rs) 的 `migrate()` 函数中按版本号递增执行。

```rust
pub fn migrate(conn: &Connection) -> Result<(), String> {
    let version: i32 = conn.pragma_query_value(None, "user_version", |r| r.get(0)).unwrap_or(0);
    if version < 1 { migrate_v1(conn)?; }
    if version < 2 { migrate_v2(conn)?; }
    // ...
}
```

### 6.2 新增迁移规则

1. 新建 `migrate_v{N}` 函数
2. 在 `migrate()` 中添加 `if version < N` 判断
3. 迁移结束时调用 `conn.pragma_update(None, "user_version", N)`
4. 使用事务包裹 DDL/DML 操作
5. 为 admin 角色添加新模块的默认权限

### 6.3 当前数据库版本

| 版本 | 迁移内容 |
|------|---------|
| v1 | 初始化：users、role_permissions、operation_logs、system_config |
| v2 | 新增 roles、user_roles 表 |
| v3/v8 | 扩展 operation_logs 表字段（客户端信息） |
| v9 | users 表添加 password_version（Token 主动注销） |
| v10 | users 表添加 must_change_password（首次登录强制改密） |

### 6.4 完整表结构

```sql
-- 用户表
CREATE TABLE users (
    id TEXT PRIMARY KEY,
    username TEXT NOT NULL UNIQUE,
    password_hash TEXT NOT NULL,           -- bcrypt 哈希（cost=12）
    real_name TEXT NOT NULL DEFAULT '',
    phone TEXT DEFAULT '',
    email TEXT,
    avatar TEXT DEFAULT '',
    status INTEGER NOT NULL DEFAULT 1,     -- 1=启用, 0=禁用
    must_change_password INTEGER NOT NULL DEFAULT 0,
    password_version INTEGER NOT NULL DEFAULT 1,
    last_login_at TEXT,
    created_at TEXT DEFAULT (datetime('now', 'localtime')),
    updated_at TEXT DEFAULT (datetime('now', 'localtime'))
);

-- 角色表
CREATE TABLE roles (
    id TEXT PRIMARY KEY,
    name TEXT NOT NULL UNIQUE,
    description TEXT DEFAULT '',
    is_system INTEGER NOT NULL DEFAULT 0,  -- 1=系统角色，不可删除/改名
    created_at TEXT DEFAULT (datetime('now', 'localtime')),
    updated_at TEXT DEFAULT (datetime('now', 'localtime'))
);

-- 角色权限表
CREATE TABLE role_permissions (
    id TEXT PRIMARY KEY,
    role_name TEXT NOT NULL,
    role_id TEXT,
    permission_key TEXT NOT NULL,          -- 格式: "模块:操作" 或 "模块"
    created_at TEXT DEFAULT (datetime('now', 'localtime')),
    UNIQUE(role_name, permission_key)
);

-- 用户角色关联表
CREATE TABLE user_roles (
    id TEXT PRIMARY KEY,
    user_id TEXT NOT NULL,

    created_at TEXT DEFAULT (datetime('now', 'localtime')),
    UNIQUE(user_id, role_id),

    ip_address TEXT NOT NULL DEFAULT '',
```

## 七、认证机制

### 7.1 Token 生成与验证

- 算法：HMAC-SHA256
- 格式：`token_{user_id}_{timestamp}_{password_version}_{hex_signature}`
- 有效期：24 小时
- 密钥：应用启动时随机生成（每次重启所有 Token 失效）

### 7.2 Token 主动注销

`users.password_version` 字段实现 Token 主动失效：
- 修改密码 → `password_version + 1`
- Token 中的 `password_version` 与数据库不一致 → Token 失效
- 管理员重置用户密码也会使该用户 Token 失效

### 7.3 前端 Token 存储

- 存储位置：`localStorage` key `gl-auth`
- 存储格式：JSON `{ t: "混淆后的Token", u: {...用户信息} }`
- 混淆方式：XOR + Base64（非加密，仅防明文暴露）

```tsx
/** @file 商品管理 - 商品列表、新增编辑、状态管理 */
export default function ProductListPage() {
  // 1. 权限控制
  const { hasAction } = usePermission()
  const canAdd = hasAction('product', 'add')
  const canEdit = hasAction('product', 'edit')
  const canDelete = hasAction('product', 'delete')

  // 2. 列表状态
  const [loading, setLoading] = useState(false)
  const [dataSource, setDataSource] = useState<Product[]>([])
  const [total, setTotal] = useState(0)
  const [page, setPage] = useState(1)
  const [pageSize, setPageSize] = useState(20)
  const [keyword, setKeyword] = useState('')

  // 3. 搜索防抖
  const debouncedSetKeyword = useDebouncedCallback((val: string) => {
    setKeyword(val)
    setPage(1)   // 搜索时重置页码
  }, 300)

  // 4. 弹窗状态
  const [createOpen, setCreateOpen] = useState(false)
  const [editOpen, setEditOpen] = useState(false)
  const [editingItem, setEditingItem] = useState<Product | null>(null)

  // 5. 数据加载（useCallback + useEffect）
  const fetchData = useCallback(async () => {
    setLoading(true)
    try {
      const res = await getProducts({ page, page_size: pageSize, keyword: keyword || undefined })
      setDataSource(res.items)
      setTotal(res.total)
    } catch {
      message.error('获取列表失败')
    } finally {
      setLoading(false)
    }
  }, [page, pageSize, keyword])

  useEffect(() => { fetchData() }, [fetchData])

  // 6. 表格列定义（ColumnsType）
  const columns: ColumnsType<Product> = [
    // ... 列定义
  ]

  // 7. 渲染
  return (
    <div className="space-y-4">
      {/* 搜索栏 */}
      <div className="rounded-xl p-5" style={{ background: 'var(--gl-card-bg)', border: '1px solid var(--gl-border)' }}>
        <div className="flex items-center gap-3">
          <Input.Search placeholder="搜索..." allowClear style={{ width: 260 }} onChange={(e) => debouncedSetKeyword(e.target.value)} />
          <Button icon={<ReloadOutlined />} onClick={fetchData}>刷新</Button>
          <div className="flex-1" />
          {canAdd && <Button type="primary" icon={<PlusOutlined />} onClick={() => setCreateOpen(true)}>新增</Button>}
        </div>
      </div>

      {/* 表格 */}
      <div className="rounded-xl" style={{ background: 'var(--gl-card-bg)', border: '1px solid var(--gl-border)' }}>
        <Table rowKey="id" size="small" loading={loading} columns={columns} dataSource={dataSource}
          scroll={{ x: 1100 }}
          pagination={{ current: page, pageSize, total, showSizeChanger: true, showQuickJumper: true,
            pageSizeOptions: ['10', '20', '50'], showTotal: (t) => `共 ${t} 条`,
            onChange: (p, ps) => { setPage(p); setPageSize(ps) } }} />
      </div>

      {/* 弹窗 */}
      <CreateModal open={createOpen} onClose={() => setCreateOpen(false)} onSuccess={fetchData} />
      <EditModal open={editOpen} onClose={() => setEditOpen(false)} onSuccess={fetchData} item={editingItem} />
    </div>
  )
}
```

## 十七、错误处理规范

### 17.1 后端错误处理

- 数据库错误通过 [src-tauri/src/error_util.rs](file:///d:/AI/AI/JXC/GLTauriRust/src-tauri/src/error_util.rs) 的 `translate_db_error` 翻译为中文
- 支持 NOT NULL → "必填字段不能为空"、UNIQUE → "用户名已存在" 等自动翻译
- 业务错误直接返回 `Result::Err("中文错误消息")`

### 17.2 前端错误处理

- **API 调用**：使用 `handleApiError(err, '默认消息')`，自动弹 `message.error`
- **表单提交**：使用 `handleFormSubmitError(err, '默认消息')`，跳过 Ant Design 校验错误
- **鉴权错误**：`api.ts` 自动拦截并登出跳转，业务代码无需处理（`AuthError` 会被 `handleApiError` 静默忽略）

### 17.3 操作日志记录

- 后端关键操作后调用 `record_operation_log(conn, username, action_type, action, module, detail)`
- 前端点击菜单时自动记录页面访问日志（`recordPageView`）
- 日志自动采集：计算机名、IP、MAC、操作系统、应用版本
