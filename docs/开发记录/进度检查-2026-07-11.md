## 四、风险与后续建议

| # | 建议 | 优先级 | 说明 |
|---|------|--------|------|
| 1 | **确认并同步版本号** | 高 | 若 v0.6.0 确已完成：bump 三处版本文件 → 0.6.0、补 `specs/releases/v0.6.0.md`、更新路线图与 project_config。*涉及发版，需用户明确确认后执行* |
| 2 | **重写开发路线图** | 高 | 将文档基线拉齐到当前真实状态（v0.5.5 + 待定 v0.6.0），删除过时规划 |
| 3 | **关联远程仓库** | 中 | 当前仅本地 `.git`，建议 `git remote add origin <url>` 后 `git push`，防止本地磁盘故障导致备份丢失 |
| 4 | **固化提交纪律** | 中 | 后续每完成一个功能，按 TDD 流程：编码 → 版本文档同步 → `git commit` → 发版 `git tag` |

## 五、版本控制常用命令参考

```bash
git status                 # 查看工作区状态
git log --oneline          # 查看提交历史
git add -A                 # 暂存全部改动（已忽略产物自动排除）
git commit -m "feat: ..."  # 提交
git tag v0.6.0             # 发版时打标签（需用户确认）
git remote add origin <url> && git push -u origin master   # 关联并推送远程
```
